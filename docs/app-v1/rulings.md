## Ruling 1（R1）技術構成

**決定**: Vite ＋ TypeScript（UI層のみ）＋ Preact。エンジン（src/v2 の純粋モジュールとブラウザ依存モジュール）は **JS のまま `src/engine/` へ移設**し、`node --test test/engine/*.test.js` を維持する。TS 化はしない（`allowJs` で型だけ拾う）。PWA は `vite-plugin-pwa`（Workbox）。UI の自動テストは Playwright（既存 `tools/check-ui-accessibility.js` を移植）。後のストア配信は Capacitor。
補足の縛り:
- `?v=` キャッシュバスターは移設時に全て剥がす（Vite がハッシュ付与するため不要。現状 `audio-engine.js` → `voice-pack-loader.js?v=…` の内部 import が二重インスタンス化の元）。
- `cache:'no-store'` は `voice-pack-loader.js` から外し、fetch 実装を注入する既存の口（`fetchImpl`）で呼び出し側がキャッシュ方針を決める。
- 端末依存（AudioContext・MediaRecorder・IndexedDB・ファイル・共有・WakeLock）は `src/app/platform/` の薄いアダプタ越しにだけ触る。Capacitor で差し替える面をここに限定する。
- フレームワークの候補は Preact / Svelte / Lit。Preact を選ぶ理由は、サブエージェント（Sonnet/Opus）が React 流儀で最も誤りが少なく、バンドルが約4KB で、Capacitor WebView でも軽いから。

**理由**: エンジンは約89件のテストで守られた資産で、TS 化は価値よりリスクが大きい。UI は全面作り直しなので型とコンポーネント化の恩恵が最大。ビルド工程を入れるのは PWA（precache manifest・ハッシュ名）とストア包みのため。

**外れた時の代償**: Preact が合わなければ UI 層だけ捨てて Svelte 等に替えられる（エンジンとアダプタは温存）。Vite を入れたことで `python3 -m http.server` の手軽さは失うが、`npm run dev` 1コマンドで同等。

## Ruling 2（R2）画面構成と導線

**決定**: 下タブ3つ「練習・ルーティン・設定」。生徒の最短経路は **ホームの種目タイル → 再生ボタン＝2タップ**。2回目以降はホーム最上段に「前回: ワルツ ▶」カードを置き **1タップ**で再生開始。先生向け機能（声の録音・配る）は **設定タブ内の「声」**に入れ、ホームには出さない。「受け取る」は設定 →「声」→「ファイルから受け取る」の生徒操作（先生の案内文で誘導）。詳細は design-skeleton.md §1–2。
→ **D1・Ruling 16 で一部変更**: ホームに「先生の声で練習」カード（種目タイルの上）を置き、S7 へ直行できる。設定タブ内の入口も残す。

**理由**: 60〜70代の初見者は「最初の画面で何を押すか」が全て。種目名だけを大きく並べれば説明が要らない。先生機能を同じ画面に置くと選択肢が増え、初見者が迷う。

**外れた時の代償**: 先生が「録音機能が見つからない」と言う可能性。対策は設定タブに「先生の方へ」の見出しを立てること。ホームへ戻すのは1日の作業で済む。

## Ruling 3（R3）ルーティン作成時のフィガー候補

**決定**: **カウントの候補は出さない**。出すのは (a) その種目の検証済みテンプレート（`dance-profiles.templates`、例 ワルツ `123`・`12&3`）を「よく使うカウント」のボタンとして、(b) フィガー**名**の入力補助として `figure-terminology` の日英名（verified のもののみ。名前だけで、カウントは付けない）。未監修の旧ルーティン24本と 317 フィガーのカウントは公開ビルドに含めず、`tools/` と開発用ページに残す。

**理由**: HANDOFF の公開条件（内容レビュー済み・根拠あり）を満たさないカウントを初心者に見せる経路を作らない。名前だけなら誤った踊り方を教えることにならない。plan.md の「未監修の旧ルーティンは公開版から外す」推測はこれで確定。

**外れた時の代償**: 先生がルーティンを組む手間が増える（1フィガーあたり名前＋カウント入力）。後で監修済みカタログができたら、同じ入力補助の口に「候補」として差し込める（データ側の `reviewStatus` で出し分け）。

## Ruling 4（R4）配布ファイルの形式と受け渡し

**決定**:
- 形式: **1ファイル JSON**、拡張子は `.json`（iOS の LINE／Files が確実に扱うため独自拡張子にしない）。中身は `{schemaVersion:1, type:"dance-count-bundle", voicePack?, routines?[]}`。`voicePack` は既存 `exportRecordedVoicePack` の出力（base64 埋め込み、schemaVersion 1）をそのまま内包し、既存の単体パック JSON も**読み込みで受理**する（互換）。ファイル名は `声-<先生名>-<日付>.dancecount.json`（英 UI では `voice-<name>-<date>.dancecount.json`）。
- 先生の書き出し: `navigator.share({files})` が使える端末では共有シートに直接出す（LINE/メール/AirDrop を選べる）。使えなければダウンロード。
- 生徒の取り込み: **アプリ内「ファイルから受け取る」＝ファイル選択**が全プラットフォーム共通の正。Android Chrome の PWA は `share_target`（files）も登録し、LINE から「共有 → アプリ」で直接受け取れるようにする。iOS は共有ターゲット不可のため、「LINE で開く → 共有 → "ファイル"に保存 → アプリで受け取る」の4手順を**アプリ内に図解**し、先生の配布文（コピーできる定型文）にも手順を含める。
- 1ファイルの目安サイズ: 12語 × 約20〜40KB → 0.3〜0.6MB（LINE 添付は問題ない範囲）。上限は 20MB で受理を拒否する。

**理由**: 既にテスト済みの書き出し形式を核にすれば最小変更。サーバー無しの制約下で最も確実なのは「ファイル選択」。iOS の share-target 非対応は既知の壁なので、技術で埋めずに手順を製品に組み込む。

**外れた時の代償**: iOS 生徒の取り込み手順が4手順と長く、ここで脱落が出る。脱落が多ければ次版で「リンク共有（小さなサーバー）」を前倒しする（plan.md の「後で」）。

## Ruling 5（R5）日本語の標準音声

**決定**: 開発時に Google Cloud TTS（`ja-JP-Neural2-B` を第一候補、`-C/-D` を比較候補）で `count-vocabularies.js` の ja-JP 12語を生成し、既存 `tools/generate-google-voices.js` → `tools/measure-voice-onsets.js` で onset 実測、manifest schemaVersion 2 で `public/audio/default-ja-female-v1/` に同梱する。**採用ゲート**: 12語すべて (1) onset 実測済み、(2) ひとみうさが試聴して「数え言葉として自然」と判定、(3) `timing:audit` 相当の鳴り合わせ確認。1語でも不自然なら、その語だけ speakingRate／SSML（`<say-as>` や句読点）を調整して再生成。それでも駄目なら日本語標準音声は **人の録音（ひとみうさ）**に切り替える（録音パックの仕組みで同梱できる）。実行時 API 依存は禁止のまま。

**理由**: 英語で確立した手順の再利用が最短。短い単音（「に」「ご」）は TTS が不自然になりやすいので、聴感ゲートを明文化しておく。

**外れた時の代償**: TTS 不採用なら公開が録音の都合で数日ずれる。録音パックは既存形式で同梱できるため実装は増えない。

## Ruling 6（R6）iPhone の落とし穴への対策

**決定**（事実確認の記録 F1〜F5 参照）:
1. **マナーモード**: 起動時に `if ('audioSession' in navigator) navigator.audioSession.type = 'playback'` を設定（WebKit 関係者の案内。Apple 公式文書ではない＝実機確認必須）。さらに再生ボタンの**同じタップ内**で AudioContext を生成・`resume()`・無音バッファ再生（ロック解除）。`statechange` で `suspended` / `interrupted` を検知したら再生を止め、画面に「もう一度 ▶ を押してください」。
2. **鳴らない時の案内**: 再生開始から2秒以内に AudioContext が `running` にならない／`currentTime` が進まない場合、画面上部に「音が出ない時は: 横のスイッチ（マナーモード）を確認・音量を上げる・イヤホンの接続を確認」を出す。設定に常設の「音が鳴らない時」ページを置く。
3. **スリープ防止**: 再生開始のタップ内で `navigator.wakeLock.request('screen')`、`visibilitychange` で再取得。取得できない端末（iOS 18.3 以前のホーム画面アプリ等）では、再生画面に一度だけ「練習中は画面が暗くなることがあります。自動ロックを長めにすると便利です」を表示。音は AudioContext が生きている限り画面が暗くなっても続く前提にしない（確認項目に入れる）。
4. **Bluetooth 遅延**: 自動補正はしない。メトロノームと声は同じ音声クロックで鳴るので互いにずれない。画面のハイライトだけ `audioContext.outputLatency`（Safari 18.4 以降で取得可）を**表示側で**足す。取れなければ 0。手動調整は「くわしく」の奥に ±200ms のつまみを1つ（v1 では実装を後段に回してよい）。

**理由**: すべて「第二のタイミング計算を作らない」（AGENTS.md）を守る範囲で、画面側だけで吸収する。案内文は技術用語を避けた3行以内。

**外れた時の代償**: audioSession が効かない iOS 版では「マナーモードを切ってください」の案内で逃げる。WakeLock がない端末では画面が暗くなるが音は続く（続かなければ実機確認で発覚し、`<audio>` 要素の無音ループを併用する次善策に切り替える）。

## Ruling 7（R7）高齢の方向け基準（機械チェック可能な数値）

**決定**（全て新アプリの `ui:check` に組み込む。値は 375×667 と 1280×900 の両方で検査）:

| 項目 | 基準 | 機械判定 |
|---|---|---|
| 本文文字 | 18px 以上（`font-size`）。補助文 16px 以上。14px 未満は禁止（法務ページの注記も 14px 以上） | 可視テキスト要素の computed font-size |
| 主要ボタン | 高さ 56px 以上、再生／停止ボタンは 72px 以上・幅は画面幅の 60% 以上 | `.dc-primary` の rect |
| その他のタップ対象 | 48×48px 以上（旧基準 44 から引き上げ）、隣接タップ対象の間隔 8px 以上 | button/a/select/input/summary/label の rect と隣接距離 |
| 1画面の主要操作数 | 初期表示（スクロール無し）で押せる操作は **5個以下**（タブバー除く）。画面全体でも 9個以下。超える分は「くわしく」の折りたたみへ | 可視 interactive 要素の数 |
| 選択肢の数 | 1つの選択 UI の選択肢は 10 以下（種目10が上限根拠）。セレクトではなく大きなボタン群かリストで出す | `<select>` の option 数、`.dc-choice` の子数 |
| コントラスト | 文字 4.5:1 以上、24px 以上の太字は 3:1 以上、アイコン・枠線・無効状態も 3:1 以上 | 既存計算の拡張 |
| 色だけに頼らない | 状態は色＋形（アイコン・塗り）＋文字で示す | 手動レビュー項目（チェックリスト） |
| 動き | `prefers-reduced-motion` で装飾アニメ全停止。拍のハイライト以外に自動で動く要素なし。遷移は 300ms 以下 | CSS の `animation-duration`/`transition-duration` ≤ 300ms、reduced-motion 時 0 |
| 拡大 | `user-scalable=no` 禁止。200% 拡大で横スクロールが出ない | meta viewport の検査、ズーム時の `scrollWidth` |
| 行の長さ | 本文は全角 35 字（英 70 字）以内で折り返す。ボタン文言は最大 2 行、はみ出し禁止 | `scrollWidth > clientWidth` 検査（既存） |
| 言葉 | 下の言い換え規則。禁止語が UI 文言に出たらテスト失敗 | `ui-messages` の文字列を禁止語リストで走査 |
| 確認ダイアログ | 質問は1つ、ボタンは2つまで、取り消し側が左 | 手動レビュー項目 |

言い換え規則（日本語 / 英語）— 禁止 → 使う語:
- BPM → 「速さ」（数値は「♩=84」の形で小さく併記）/ "Speed"
- インポート／エクスポート／読み込み／書き出し → 「受け取る」「配る」「ファイルに保存」 / "Receive" "Share" "Save file"
- ルーティン → そのまま可（ダンサーの日常語）。「フィガー」も可
- メトロノーム → そのまま可。説明は「カチカチ音」
- カウントイン → 「はじめの合図」/ "Lead-in"（英は "Count-in" 可）
- 音声パック／ボイスパック → 「声」/ "Voice"
- 設定を保存／ストレージ／キャッシュ／同期／エラーコード → 使わない
- 「〜してください」で終わる依頼は1画面1つまで。エラー文は「何が起きたか」＋「次に押すもの」の2文構成

**理由**: 前回設計の 18px/44px/4.5:1 は維持しつつ、初見・高齢向けに「数」と「言葉」を機械で縛る。基準を数値にしておけばサブエージェントが勝手に詰め込めない。

**外れた時の代償**: 画面数が増え、慣れた人には1タップ余計になる。「くわしく」の中に逃がすので経路は壊れない。

## Ruling 8（R8）法務

**決定**:
- プライバシーポリシー（日英）を設定タブから到達できる静的ページとして同梱。内容の芯: 録音・ルーティンは端末内にのみ保存、運営者はデータを受け取らない、解析ツールなし（**v1 は解析を入れない**）、ファイルの受け渡しはユーザー自身が行う。
- マイク: OS の許可ダイアログの**前**に自前の説明画面（何を録るか・端末内にだけ保存・いつでも削除）を出し、「録音をはじめる」ボタンのタップで初めて `getUserMedia`。
- 声の配布: 「配る」操作時にチェック1つ「自分の声をこのファイルに入れて配ることに同意します。配り先は自分で管理します」。ファイルに `consent:{distributor:<先生名>, consentedAt}` を記録。受け取り側には「○○さんの声」と表示し、削除ボタンを声一覧に常設。
- 「公式・監修済みとは名乗らない」の表現を About に明記（団体名・級は出さない）。
- 運営者名義は **ひとみうさ判断**（下 Q4）。

**理由**: サーバーを持たない設計なので個人情報処理が最小で、地域別ポリシー（globalization-architecture）も v1 は日英共通で足りる。ストア版では Apple のプライバシー表示が要るため、今から「解析なし・外部送信なし」を事実にしておくと後が楽。

**外れた時の代償**: 解析なしなので利用状況が分からない。反応はストア前にユーザーの声で測る。

**決定**: 旧ルーティン・移行レビュー・音声比較の各ページ（`routine-migration-review.html` 等）は新アプリに**含めない**。旧 `public/` は `legacy/` へ移してそのまま動く状態で残し、`html-module-syntax.test.js` と `ui-assets.test.js` はパスを追従させて維持する。

## Ruling 11（追加）保存先と消失対策

**決定**: ルーティン・声・設定は **IndexedDB**（既存 DB `dance-count-v2` のバージョンを上げ、`routines`・`settings` ストアを追加。localStorage の下書き形式は読み取り互換のみ残す）。初回保存成功時に `navigator.storage.persist()` を要求。先生の録音完了時とルーティン保存時に「ファイルに保存（バックアップ）」を勧める1行を出す。
**理由**: iOS の未使用7日消去はホーム画面アプリでは緩和されるとされるが Apple の明文は見つからず（F5）。消えて困るのは先生の録音なので、ファイル保存を製品の動線に組み込む。
**代償**: 勧めが煩わしい。表示は各1回だけ。

## Ruling 12（追加）表示言語とカウント音声の言語

**決定**: UI 言語は端末言語から `resolveUiLocale` で決め、設定タブと初回ホーム右上の地球アイコンで切替。カウント**音声**の言語は UI と独立の設定（globalization 方針）。初期値は Q3 の回答で決める。
**代償**: 独立設定は設定項目が1つ増える。「声」画面の中に収める。

## Ruling 13（追加）練習画面の初期値と「くわしく」

**決定**: 初期値＝繰り返しオン・メトロノームオン・はじめの合図1小節・速さ「標準」（`practiceBpm`）。表に出す操作は「速さ3択（ゆっくり／標準／速め）・メトロノーム・はじめの合図・声」＋再生。「くわしく」の中に: 速さの細かい調整（スライダー 40〜220）・競技の速さ（`competitionBpm` 範囲）・繰り返しオフ・声のタイミング微調整。「ゆっくり」＝標準の 80%、「速め」＝標準と競技下限の中間（値は dance-profiles から算出、定数化）。
**理由**: Ruling 7 の「初期表示5操作以下」を満たしつつ、現行の機能を捨てない。
**代償**: スライダー派は1タップ増える。

## Ruling 14（追加）Android/PC の扱い

**決定**: 対応はするが設計の基準端末は iPhone（375px）。Android Chrome は `share_target` と `beforeinstallprompt` の案内を追加。PC は 1280px で同じ画面が崩れないこと（2カラム化はしない）。
**代償**: PC で余白が多い。v1 では許容。

## Ruling 15（追加）録音の形式

**決定**: 録音は現行どおり `MediaRecorder`（iOS は `audio/mp4`、Chrome は `audio/webm;codecs=opus`）→ `recording-normalizer` で WAV 化して保存・配布する（配布ファイル内は WAV、既存形式のまま）。再生側の decode 互換の心配をなくす。
**代償**: ファイルがやや大きい（Ruling 4 の見積もりは WAV 前提で約 0.5〜1MB）。LINE 添付に支障なし。

## 追加裁定（2026-10-11・D1〜D8 を受けて）

## Ruling 16（D8-(1)）「先生の声で練習」カードの置き場

**決定**: カードは **種目タイルの上**（「前回: ○○ ▶」カードの直下、初回起動なら見出しの直下）に、横幅いっぱい・高さ 56〜64px の1行（マイクのアイコン＋「先生の声で練習」＋右向き山形）で置く。タップ先は S7（声の一覧。録音・受け取るの2ボタンを含む）。種目タイルは1行 64〜72px に収め、**375×667（タブバー込み）の初期表示にカードと10種目すべてが入る**ことを `ui:check` の判定に加える（カードの rect と各タイルの rect が最初のビューポート内）。D1 の「種目タイルの下」は、この位置では1画面目に入らないため上に改める（PO 方針「前に出す」を優先）。
**理由**: 目玉を「見える位置」に置きつつ、生徒の最短経路（タイル→▶）を1行ぶん下げるだけで済む。種目を選ぶ見出しは残るので初見者の迷いは増えない。
**外れた時の代償**: 生徒が毎回「先生の声」を目にして押してしまう可能性。S7 は「戻る」で即戻れ、何も壊れない。

## Ruling 17（D8-(2)）「戻る」と下タブの出し分け

**決定**: 画面を2種に分ける。
- ルート画面（S1・S3・S6）と一覧画面（S7・S12・S13）: 下タブを表示。「戻る」は一覧画面のみ左上に表示。
- 集中画面（S2・S5・S4・S8・S9・S10・S11）: 下タブを**隠し**、左上に必ず「‹ 戻る」（48px 以上、山形＋文字ラベル、アイコン単独禁止）。下固定の主ボタン（▶／全体を試聴／録音する／ファイルを作る）はタブバーと同居させない。
- 「戻る」は再生中なら音を止めて戻る（確認なし）。S8 は録音済みの語を保存した上で戻る（確認なし、再開可）。
- ブラウザ／端末の戻る操作は同じ動きにする（ハッシュ履歴に画面ごとに1件積む）。
**理由**: 60〜70代の初見者にとって「戻れない」は最大の不安。集中画面で下タブを隠すのは、下に ▶ とタブが並ぶと誤タップが増えるため。
**外れた時の代償**: 集中画面からタブ直行ができず1タップ増える。許容。

## Ruling 18（D8-(3)）「1画面の主要操作数」の数え方（機械判定）

**決定**: 375×667・スクロール無しの初期ビューポートで、次を数える。
- 対象: 可視の `button, a, [role=button], input, select, summary, label[for]`。rect が初期ビューポート内に**完全に**入るもの。
- 除外: `[data-nav]`（下タブ）、`[data-back]`（戻る）、`[data-utility]`（言語切替など右上の補助）。
- まとめ: 同じ `[data-group]` 祖先を持つ要素は **1操作**として数える（速さ3択＝1、種目タイル10個＝1、カウントの型チップ群＝1）。`[data-group]` の中の選択肢は 10 個以下（Ruling 7 と同じ）。
- `summary[data-more]`（「くわしく」）は主要操作に数えないが、1画面に 1 個まで。
- 上限: **初期表示 5 以下**、画面全体（スクロール含む）9 以下。
- 当てはめ: S1＝前回カード(1)＋先生の声(1)＋種目タイル群(1)＝3。S2＝速さ(1)＋メトロノーム(1)＋はじめの合図(1)＋声チップ(1)＋▶(1)＝5。したがって **カウントの型チップ（ワルツ `1 2 3`/`1 2 & 3` 等）は「くわしく」の中へ**、初期値は `templates[0]`。選んだ型は種目ごとに記憶する。
**理由**: 「要素数」でなく「判断の数」を数えれば、グループ化で画面を整理する動機になる。属性で宣言させればサブエージェントの実装も検査も機械的。
**外れた時の代償**: ワルツの `12&3` 派が1タップ余計。種目ごとに記憶するので2回目以降は影響なし。

## Ruling 19（D8-(4)）S2 のトグルは Ruling 13 のまま

**決定**: 表に出すトグルは **メトロノーム・はじめの合図** の2つ。繰り返しは初期オンで「くわしく」の中。比較 HTML（b-studio-navy.html）の「繰り返す」は清書時に「はじめの合図」へ差し替える（モックの作り直しは不要）。
**理由**: はじめの合図は「▶ を押した直後に何が起こるか」を変えるので、初見者が最初に調整したくなる設定。繰り返しはほぼ常にオンで、変えるのは慣れた人。
**外れた時の代償**: 繰り返しを切りたい人が「くわしく」を開く1タップ。

## Ruling 20（D7）曲を載せる口 — v1 の最小インターフェース

**決定**: v1 では **テンポ写像（TempoMap）の抽象化だけ**を作り、曲の音・画面・同梱・計測ツールは作らない。
- 作るもの（v1）:
  1. `src/engine/tempo-map.js`（純粋モジュール）: `tickToMs(tick)` / `msToTick(ms)` を持つ2実装。`constantTempo(bpm)`（現在の `tick × 60000 / (bpm × 960)` と同値）と `beatMapTempo(beatsMs[], beatsPerBar)`（拍ごとの実測時刻の間を区分線形補間。範囲外は最後の拍間隔で外挿）。単体テストで (a) constant が現行計算と全 tick で一致、(b) beatMap が拍時刻をちょうど返す、(c) 単調増加、を固定。
  2. `audio-engine.js` と `timeline-view-model.js` の「tick → 秒」をこの1箇所に集約（constant を既定で注入）。**第2の時間計算は作らない**: メトロノーム・声・ハイライトは引き続き同じ tick 列から、同じ TempoMap で秒に変換する。移設後の `timing:audit` の diff ゼロが完了条件（constant 経路は数値が変わらないこと）。
  3. データの型だけ定義（実データなし）: `TrackProfile { id, danceId, title, file, durationMs, beatsPerBar, tempo: {kind:'constant', bpm, firstBeatMs} | {kind:'beatMap', beatsMs:number[]}, license:{kind:'CC0'|'PD-recording'|'CC-BY', source, url, note}, measuredAt }`。練習セッション状態に `track: null` の席を予約。
- 作らないもの（第2弾）: 曲の音の再生（AudioBufferSource を tick 0 ＝ `firstBeatMs` に合わせて開始する処理）、曲の選択 UI（S2 の「くわしく」に「曲に合わせる」として入れる予定）、曲の同梱とライセンス台帳、拍位置の計測ツール（`tools/measure-track-beats.js`）、ユーザー自身の曲の読み込み（範囲外、D7）。
- 第2弾での前提を今決めておく: 曲ありのときは速さ3択を無効（タイムストレッチはしない。曲の実測テンポで鳴らす）、カウントインは曲の先頭無音部の長さで代替、ルーティンは曲より長ければ曲の末尾で停止。
**理由**: 今の「tick→秒」を抽象化しておけば、第2弾は「TempoMap を曲のものに差し替えて音源を同時に始める」だけで済み、エンジンの構造を再度いじらない。v1 の公開は遅れない（純粋モジュール1本＋テスト）。
**外れた時の代償**: 生演奏のテンポ揺れが拍の区分線形で足りない場合（ルバートが極端な曲）は曲の選定で避ける。抽象化が不要になっても constant 実装がそのまま残るだけで害はない。

### Ruling 20 訂正メモ（2026-10-11・段1実装時）
- tick→秒の集約対象は `audio-engine.js`・`rhythm-compiler.js`・`dance-timing-audit.js`。`timeline-view-model.js` に該当計算はない。
- beatMap の外挿は、最初の拍より前は最初の拍間隔、最後の拍より後は最後の拍間隔。
- 関連（Ruling 21）: 1024px 以上の上部タブは段2で実装する（段1は下タブのみ）。

## Ruling 21（§16-1）PC 幅のレイアウトとタブの位置

**理由**: PO が選んだモックの PC 図（S2 2カラム・上部ナビ）を「同じ部品の並べ替え」として受け入れれば、Ruling 14 の目的（PC 専用の作り込みで工数を増やさない）と矛盾しない。

## Ruling 22（§16-2）拍子の副題はやめ、「最初に鳴るカウント」を副題にする

**決定**: 種目タイル（S1）と再生画面の見出し（S2/S5）の副題は「N拍子」ではなく、**その種目の `templates[0]` を表示用に整形したカウント**にする（例: ワルツ「1 2 3」、タンゴ「S S Q Q S」、スローフォックス「S Q Q」、サンバ「1 a 2」、パソドブレ「1 2 3 4」、ジャイブ「1 2 3 a 4 5 a 6」）。整形は現在カウント表示と同じ関数（声キー→表示語、`&`→「&」、`a`→「a」、日英共通）。拍子（2/4・3/4・4/4）は**どこにも表示しない**。エンジンの `beatsPerBar`（パソドブレ 4・サンバ 2）はそのまま。
**根拠の確度**: パソドブレの音楽が 2/4 で書かれることは一般的な複数資料で確認（MasterClass・Library of Dance 等。WDSF 等の規程では未確認）。エンジンがパソドブレを「1小節4拍」で数えるのは既存設計（テンプレート `1234`・`12345678`）で、ダンス上の慣習としての正しさは**本件では検証していない**。だからこそ拍子を名乗らず、「何が鳴るか」だけを見せる。
**理由**: 初見者に有用なのは「3拍子」より「1 2 3 と鳴る」こと。音楽理論の主張を UI から消せば、未検証知識を表示しない原則（AGENTS.md）にも沿う。
**外れた時の代償**: 「拍子を知りたい」人には情報が無い。要望が出たら S13 か「くわしく」に出典付きで追加する。副題が長いジャイブ（15字）は 16px でタイル幅 170px に収まる（U10 で検査）。

## Ruling 23（§16-3）警告バナー表示中の ui:check

**決定**: S2/S5 は **通常状態とバナー表示状態の両方**を検査する（テスト用クエリ `?ui-state=no-sound` でバナーを強制表示）。バナー内の操作は1つだけ（「音が出ない時は ›」リンク、`[data-alert-action]`）で、**U4 の主要操作数からは除外**し、U1・U3・U7（文字・タップ・コントラスト）は適用する。バナー状態でも `[data-group="speed"]` と `[data-play]` が 375×667 の初期ビューポートに完全に入ること（バナーの高さは 375 幅で 120px 以下）。声チップやトグルがフォールド下へ押し出されるのは許容。
**理由**: バナーは一時的で、出ている間に生徒が触るのは「もう一度 ▶」と速さだけ。例外ではなく「もう1つの状態」として検査すれば、バナーで画面が壊れる事故を機械で防げる。
**外れた時の代償**: バナー文を長くできない（3行以内）。S11 に詳しい説明を置くので足りる。

## Ruling 24（§16-6）速さ3択の定義（ワルツ問題）

**決定**: 「ゆっくり」＝`round(practiceBpm × 0.8)`、「標準」＝`practiceBpm`、「速め」＝`min(round(practiceBpm × 1.1), competitionBpm.max)`。定数 `SPEED_SLOW_RATIO=0.8`・`SPEED_FAST_RATIO=1.1` を1か所で持つ。ワルツ: 67 / 84 / 90。他の種目は全て「速め」が標準より大きく、競技範囲の上限を超えない（例: タンゴ 123、クイックステップ 176、ジャイブ 150）。本当の競技テンポは「くわしく」の「競技の速さ」ボタン（`competitionBpm.min`）で出す。
**理由**: 「速め」は初見者にとって「少しだけ速い」であるべきで、競技テンポとの中間という定義は種目によって跳びが大きすぎた（ルンバ 80→90 は良いがクイックステップ 160→176 と同じ式でワルツが 84→84 になる）。比率なら全種目で意味が揃う。比率 0.8/1.1 は製品判断で、ダンス上の根拠はない。
**外れた時の代償**: 「速め」が競技テンポに届かない種目が多い。競技の速さは「くわしく」にあるので経路は残る。単体テストで10種目の3値が「ゆっくり < 標準 < 速め ≤ 競技上限」を満たすことを固定する。

## Ruling 25（§16-7）先生が録音する言語と選ぶ場所

## Ruling 29（Q5）Bluetooth の表示遅延はエンジンの `frame()` に表示用の遅れを渡す（計画者の推奨を却下）

**決定**: UI 側の setTimeout 遅延キューは**採用しない**。代わりに `PracticeAudioEngine` のコンストラクタオプションに `displayLatencySeconds: () => number`（既定 `() => 0`）を足し、`frame()` の経過時間だけを `elapsed = this.audioContext.currentTime - this.displayLatencySeconds() - startTime` にする。予約（`scheduleAhead`・`scheduleClick`・`start()` の戻り値）は一切触らない。
- 呼び出し側: `platform/audio-context.ts` が `() => clamp(context.outputLatency ?? 0, 0, 0.5)` を渡す（取れない・NaN・負・0.5秒超は 0）。毎フレーム読むので Bluetooth の接続・切断に追従する。
- テスト: `test/engine/audio-engine.test.js` に「latency 0.2 のとき currentTime=T の frame は、latency 0 の currentTime=T−0.2 と同じ `originalTick`・`countIn` を返す」を追加。`npm run timing:compare` と予約時刻のゴールデンは**変化ゼロ**が条件（既定 0 なので既存テストも不変）。
- 手動つまみ（±200ms）は v1 では入れない（同意）。

**理由**: 「表示だけ遅らせる」は仕様 §9「表示は currentTime（＋outputLatency）から tick を読む」そのもので、その計算は `frame()` にある。setTimeout の列は壁時計で動く第2の時計で、AGENTS.md「第2の時間計算を作らない」に反し、停止時の掃除・順序・ジッタの面倒も増える。エンジンの変更は `frame()` の1行＋オプション1つで、onFrame の出力契約は変わらない。

**外れた時の代償**: `src/engine` に手を入れる例外が1つ増える（仕様 §10）。範囲は `frame()` のみと明記し、レビューで予約経路に触れていないことを diff で確認する。

## Ruling 38（Q5・Q6）[仕様差] 「使える記号」は種目ごと、入力は正規化してから検証

**決定**: Q5・Q6 とも計画者の推奨に同意。具体値:

**理由**: 固定文言は種目ごとの可否と食い違い、ワルツで `a` を打った先生が迷う（事実）。保存値を打った文字から変えるのは「パーサのトークンを変えない」原則の範囲内（トークンは同じ、表記ゆれを吸収するだけ）。

**外れた時の代償**: 先生が空白や `|` で区切る癖があっても保存されない（表示は空白区切りなので実害なし）。

## Ruling 49（D11）フィガーの並べ替えのドラッグ — つかみ・見た目・タッチとスクロールの両立

前提: D11 で発見 #21 を取り消し、S4 のフィガーの行をドラッグで並べ替えられるようにする。「上へ」「下へ」（Ruling 36-3）が主、ドラッグは補助（仕様 §4 S4 の原文どおり）。基準は 60〜70代の先生。コードで確かめた事実: 旧画面 `legacy/routine-editor.html` はタッチを ⠿ 限定の Pointer Events、マウスは HTML5 drag（行本体と ⠿）、キーボードは ⠿ 上の上下矢印、挿入位置は 3px の線、確定は `state.moveFigure`（元に戻す 1 回分）。`src/engine/routine-editor-order.js` の `dropDestination(from, target, placeAfter, count)` は純粋関数で、そのまま使える。`RoutineEditorState.moveFigure` は from＝to なら何もしない（元に戻す履歴も積まない）。

**決定**: 計画者の推奨に**おおむね同意**。変える点・足す点を番号で固定する。

1. **つかむ場所＝閉じた行の右端の「つかみ」**（同意）。`<button type="button" class="dc-grip">`（`role="button"` の div ではなく本物のボタン。フォーカス・Enter/Space が自動で付く）。行の見出し `.dc-figure-head` の**外**に置く（兄弟）。行の中は `.dc-row-line{display:flex; align-items:stretch; gap:10px}` に見出し（`flex:1; min-width:0`）＋つかみ（`flex:none`）。番号・名前・カウント・˅ は見出しのまま（S3 と同じ `.dc-row-head`。変えない）。左端は琥珀の線と番号があるので右。右手の親指でも届く。
2. **つかみの寸法と中身**: 幅 **56px**・高さは行の見出しに合わせて伸びる（最小 48px）。中は縦積み: ⠿ アイコン（24px、6 点・2 列×3、`fill: currentColor` の円。play/stop と同じ「塗り」の例外として §5 のアイコン一覧に `grip` を足す）＋**見える文字「動かす / Move」16px・600・`--ink2`**。枠・背景なし（見出しと同じ）。`touch-action: none; user-select: none; -webkit-touch-callout: none; cursor: grab`（ドラッグ中 `grabbing`）。`:focus-visible` は共通の `--focus` 3px。
   - **§5「アイコン単独のボタン禁止」との関係＝文字を添える（代案 (b)）で解消。仕様差なし。** ⠿ はこの世代に最も通じないアイコンで、aria-label だけでは目に見える説明にならない。(c) の「並べ替えモード」は入る・出るの状態を 1 つ増やし（モードから出られない事故）、主要操作数も 1 増える。一覧の上に 1 行の説明を置く案（(d)）は 13 行の一覧の 10 行目にいる時に説明が画面の外へ出るので採らない。「騒がしい」懸念は `--ink2`・16px・600 で抑える（見た目はひとみうさ判断。下の「ひとみうさ判断」参照）。
   - `aria-label="{フィガー名}を動かす"`（英 `Move {name}`）、`aria-keyshortcuts="ArrowUp ArrowDown"`。見える文字は全行同じ「動かす」でよい（読み上げは名前つき）。
3. **出す条件**: フィガーが **2 件以上**の行に出す（1 件なら並べ替えは無いので出さない）。新規の追加の行（`open.kind==='add'`）には出さない。**行が開いている時・「くわしく」が開いている時も出したまま**（計画者の「出さない」は採らない。開閉のたびに全行のつかみが消えたり出たりして一覧がちらつき、見出しの幅も変わるため）。排他（Ruling 36-2）は次の 4. で守る。
4. **押してからの分岐（Pointer Events。マウス・タッチ・ペン共通。HTML5 drag は使わない）**:
   - `pointerdown`: `setPointerCapture`。`preventDefault`（iOS の選択・コールアウト防止。`contextmenu` も止める）。この時点では**何もしない**（開いている行も閉じない）。
   - 押した点から **8px 以上**（`Math.hypot(dx,dy) >= 8`）動いたら**ドラッグ開始**。開始時に: 開いている行があれば閉じ方の原則（Ruling 36-1。有効なら確定・無効なら捨てる）で閉じる → 試聴（行・全体とも）が鳴っていれば止める → 行に `.dc-row--dragging`。開いている行自身のつかみを引いた時も同じ（閉じてから、その行を動かす）。
   - 8px 未満で離したら**タップ**＝行の見出しをタップしたのと同じ（`openRow(index)`。開いている行自身なら `close()`）。「動かす」を押して何も起きない状態を作らない。開いた行には文字つきの「上へ」「下へ」があるので、ドラッグが分からない先生はここへ落ちる。
   - `pointermove`（開始後）: `document.elementFromPoint(x, y)` から `.dc-row[data-index]` を引き、`placeAfter = y >= rect.top + rect.height/2`。一覧の上（最初の行より上）は先頭の前、下（最後の行より下、追加ボタン・下固定の帯の上）は末尾の後。横方向の位置は見ない（指が左右にずれても落とせる）。
   - `pointerup`: `dropDestination(from, target, placeAfter, count)` で行き先を求め、`RoutineEditor.move(from, to)`（新設。閉じた行の移動。`edits.moveFigure` を 1 回呼ぶだけ。from＝to なら `false`）→ `act()` の経路で**1 回の変更として確定・元に戻す 1 回分・自動保存**。確定後、動かした行のつかみにフォーカス（キーボードの続き用。タッチでは見えない）。ドラッグの直後に来る `click` は無視する（フラグ 1 つ）。
   - `pointercancel`・Esc・`blur`・`visibilitychange`: ドラッグを捨てる（何も変えない）。
5. **ドラッグ中の見た目**（動きのアニメーションなし。reduced-motion と同じ。U8 に触れる transition も付けない）:
   - 動かしている行: **`outline: 2px solid var(--primary); outline-offset: -2px`** の枠だけ。背景は白のまま（計画者の `--soft` は「開いた行」の色なので使わない。透明度 0.4 も使わない＝文字のコントラストを落とさない）。行はその場に留まり、指について動くゴーストは**作らない**（v1。旧画面と同じ方式で、線で行き先を示せば足りる）。
   - 挿入位置: **3px・`--primary`・一覧の幅いっぱい・角丸 2px** の線を、行と行の境（1px の罫線の上）に描く。先頭の前は一覧の上端、末尾の後は最後の行の下端。描き方（`::before/::after` か 1 つの絶対配置要素か）は実装者に任せる。`aria-hidden`。
   - 落とした後の「ここに来た」ハイライト（旧画面の `just-moved` 0.65s）は**付けない**（§5「自動で動かさない」・U8 300ms）。番号が変わる・フォーカスが乗る・線が消えるで足りる。
   - 一覧全体に `user-select: none`（ドラッグ中だけ）。`body` に `cursor: grabbing`（マウス）。
6. **自動スクロール**: 指が「見えている領域」の上端・下端から **48px 以内**に入ったら、`requestAnimationFrame` ごとに **8px** 固定速度（約 480px/秒。指の位置で加速しない）で `window.scrollBy`。見えている領域＝ビューポートから固定の帯を除いたもの（スマホは下の `.dc-dock`、PC は上の `.dc-tabs`。`getBoundingClientRect` で引く）。指が領域から出たら止める。スクロール中も 4. の `pointermove` の判定を毎フレーム更新する（指が止まっていても行き先は動くため、最後の座標を保持）。
7. **キーボード**: つかみにフォーカスして **↑ / ↓** で 1 つずつ移動（旧画面と同じ。`move(index, index±1)`、開いている行は 4. と同じ原則で先に閉じる）。移動後もフォーカスは同じフィガーのつかみに乗ったまま。Enter / Space はタップと同じ（行を開く）。
8. **タッチとスクロールの両立**: `touch-action: none` は**つかみだけ**。行の見出し・名前・カウントの上では指で普通にスクロールできる。つかみの上で指を置いた瞬間から画面はスクロールしない（ドラッグの準備）。長押しの待ち時間は**設けない**（置いてすぐ動かせる。待たせると「動かない」と誤解される）。
9. **主要操作数・ui:check**: つかみは `[data-list]` の中で `[data-row-body]` の外なので一覧の 1 に畳まれる。**S4 の期待値 5・7・7 は不変**（ui:check に固定したまま）。U3: つかみ 56×(≥48)、見出しとの間 10px、上下の行のつかみ同士は `.dc-row` の 4+1+4=9px（発見 #4 のまま）。U7: ⠿ と文字は `--ink2`（白 7.35・`--now-bg` 上 6.31）、枠と線は `--primary`。U10: 「動かす」3 字×16px＝48px＜56px、`Move` も入る。U8: つかみ・行・線に transition/animation を付けない。
10. **検査**:
    - 純粋関数（`src/app/routines/reorder-drag.ts`、`node --test`）: `isDragStart(dx, dy)`（8px 境界: 7.9 は false・8.0 は true）、`dropTargetFromY(rows: {top,bottom}[], y) → { targetIndex, placeAfter } | null`（最初の行より上＝0/before、最後の行より下＝last/after、行の中央ちょうど＝after、0 行＝null）、`dropDestination` との結合（13 件で 2→9、9→2、0→12、12→0、同じ位置＝変化なし）。
    - `RoutineEditor.move(from, to)`（Task 7 のテストに追加）: 開いている行を原則どおり閉じてから動く（有効なら確定が 1 回分＋移動が 1 回分＝元に戻す 2 回）、from＝to は `false` で履歴なし、範囲外は `false`。
    - Playwright（`smoke:routines` に追加・マウス）: 3 行目の `.dc-grip` を `mouse.down` → 1 行目の上端より上まで 3 段階で `mouse.move` → `mouse.up`。期待: 番号と名前の並びが変わる、`.dc-row--dragging` と線が消えている、再読み込み後も並びが残る（発見 #8 の 500ms 待ち）、「元に戻す」で戻る。もう 1 本: `mouse.down` → 4px だけ動かして `mouse.up` → 行が開く（タップ扱い）。
    - iPhone 実機確認表（`stage3-device-check`）に 5 行: (1) ⠿ を置いてすぐ上下へ動かして落とせる、(2) 名前の上で指を滑らせると普通にスクロールする、(3) 13 件で下端へ引くと自動で下へ進み、末尾に落とせる、(4) 試聴中に引き始めると音が止まる、(5) ⠿ を軽く押すと行が開く。
11. **文言（`messages.ts`）**: `move: '動かす' / 'Move'`、`moveFigureLabel: '{name}を動かす' / 'Move {name}'`。禁止語なし。

**理由**: ⠿ は便利だが、この世代には「押して引く」が自明ではない。だから (1) 見える文字で名前を付け、(2) 押しただけなら文字つきの「上へ」「下へ」へ落とし、(3) ドラッグは「上へ」「下へ」と同じ `moveFigure` に流し込んで元に戻せる 1 回の変更にする。この 3 つで、ドラッグが分からなくても困らず、分かれば速い。HTML5 drag は iOS のタッチで来ないので Pointer Events に一本化し、`touch-action: none` をつかみだけに限ることでスクロールと衝突させない。つかみを常に出すのは、開閉で一覧がちらつく方が「どこを押せばいいか」を見失わせるから。

**外れた時の代償**: 行の右に 56px を取るぶん、375px では名前の欄が約 190px になり、11 字以上の名前が 2 行に折れる（折り返しは許容。U10 の例外は不要）。全行に「動かす」の文字が並ぶ（騒がしく見えるかは実装後の画面でひとみうさが見る。騒がしければ文字を `--ink2` のまま 14px には**しない**で、代案 (d)（一覧の上に 1 行の説明、つかみはアイコンだけ＋aria-label）へ切り替える＝その時は [仕様差] として記録）。指が震えて 8px を超えると「タップのつもりが同じ位置へのドロップ」になるが、同じ位置なら何も変わらない（履歴も積まない）。ゴーストを作らないので、自動スクロール中は枠の行が指から離れて見える（線が行き先を示すので実害なし）。

**仕様の読み替え**: §4 S4 の「並べ替えは「上へ」「下へ」だけで行い、ドラッグは作らない（段3計画の発見 #21…）」を「並べ替えは「上へ」「下へ」が主。補助として、閉じた行の右端の「⠿ 動かす」（56px・文字つき）を押したまま上下へ引くと動く（8px 未満で離すと行を開く。Ruling 49）」に。§5 アイコン一覧に `grip`（塗りの例外）を足す。§5「アイコン単独のボタン禁止」はそのまま（つかみは文字つき）。§6 の当てはめ表は不変。

**計画への反映（計画者）**: Task 7 に `move(from, to)` とテスト、Task 9 に `.dc-row-line`・`.dc-grip`・`src/app/routines/reorder-drag.ts`・ドラッグのフック（`RoutineEditScreen.tsx` 内か `useReorderDrag.ts` に切り出し）・`icons.svg` の `grip` と `icon-names.ts`・文言 2 つ、Task 11 に smoke の 2 本、Task 12 の実機確認表に 5 行。発見 #21 は「D11 で取り消し（Ruling 49）」と注記。

- **D14 使える文字をいつも見せる**: カウント欄の下に、その種目で使える文字を「使える文字：1・2・3・&」の形で**常に**出す（今は間違えた時だけ「使える記号: 1 2 3 &」が出る）。— 理由: 何を打てばいいか分からない（ひとみうさの所見）。

- **D16 小節の注意は止めずに知らせる（2026-10-11）**: ひとみうさ「ワルツは3拍子なのに2拍分のカウントでもOKになっている」。全種目で「フィガーは小節ちょうど」を強制すると、タンゴ（プログレッシブリンク Q Q）・クイックステップ（S Q Q S）・ジャイブ（ベーシック 6拍）など小節をまたぐフィガーが入れられなくなる（一般的な数え方。公式資料では未確認）ので強制はしない。A 案: (1) **ワルツ・ヴィエニーズワルツ**で1フィガーが3拍の倍数でない時、その行に小さく「**3拍のカウントではありません。必要なら編集してください。**」（ひとみうさの文言）。入力・保存・再生は止めない。(2) **全種目**でルーティン全体が小節の途中で終わる時、S4 の一覧の下に1行「小節の途中で終わっています。繰り返すと頭がずれます。」。— 細部（英語・出す場所・Ruling 7 の「〜してください は1画面1つ」との関係）は Fable の裁定で決める。

## Ruling 50（D13・D14）同じ名前のフィガーは同じカウント・使える文字をいつも見せる

前提: D13・D14（段3の iPhone 実機確認）。基準は 60〜70代の先生。Ruling 36（行を開いて決定・閉じ方の原則・理由は1つずつ）・38（使える記号・正規化）・39（複製は名前そのまま）を前提に、変える点だけ書く。コードで確かめた事実: `RoutineEditor.check()` は `{ valid, counts, reason }` を返し、`reason` は `'symbols'|'leading'|'invalid'|'name'|null` の 1 つ（カウント → 名前の順）。`close()` は有効なら確定・無効なら捨てる。`duplicateOpen()` は名前そのままで直下に複製。`figure-names.ts` の `fold`＝NFKC＋小文字化（候補の照合に使用、未 export）。`counts.ts` の `allowedSymbols(danceId)` は `@` を除いて空白区切り、`normalizeCounts` は NFKC → S/Q 大文字・a 小文字 → 空白と `|` を除く。`FigureForm` の `[data-group="figure-form"]` は名前欄・候補（最大 5）・カウント欄・よく使うカウント（最大 2）・主ボタン＝最大 10（U5 の上限ちょうど）。理由の 1 行は `.dc-reason`（16px・700・`--warn-ink`・警告アイコン。名前の理由だけアイコンなし）。

### D13 同じ名前のフィガーは同じカウント

**決定**: 計画者の推奨に**おおむね同意**。原則を 1 文にそろえ、編集の行で「カウントを直したい時」に詰まる穴を塞ぐ。

**原則（1つだけ）**: **名前の仲間に入る時はその仲間のカウントを受け取る。仲間のカウントを変える時は仲間ごと変わる。** 「仲間」＝ 1. の判定で同じ名前になるフィガーの集まり。追加の行と「名前を変えた」編集の行は前者、「名前はそのままでカウントを変えた」編集の行は後者。

1. **「同じ名前」の判定**: 前後の空白を除き、NFKC → 小文字化で等しい（`figure-names.ts` の `fold` を `foldFigureName` として export し、候補の照合と**同じ 1 つの関数**を使う。判定を 2 か所に書かない）。半角カナは NFKC で全角になるので `ｳｨｽｸ`＝`ウィスク`、`Whisk`＝`whisk`。名前の中の空白は除かない（`ナチュラル ターン`≠`ナチュラルターン`。候補の照合と同じ規則にそろえるため）。比べる相手は**自分以外の行**（編集の行は自分の index を除く）。同じ名前の行が複数あれば**番号の若い行**を「仲間の代表」とし、その名前の表記とカウントを使う。
2. **追加の行（`open.kind==='add'`）**: 名前が仲間に入る時:
   - カウント欄が代表と**同じ**（正規化後に等しい）なら普通の「追加する」。理由の行なし。
   - カウント欄が**空か違う**（打ち損じで無効の時も含む）なら、理由の行「**同じ名前があります（1 2 & 3）**」（英 `Same name exists (1 2 & 3)`。括弧の中は代表のカウントを `formatCounts` で）＋主ボタンを **「複製して追加」**（英 `Add a copy`。アイコンは `copy`。同じ場所・同じ大きさ・`.dc-primary`・常に押せる）に替える。押すと**代表と同じ名前（代表の表記）・同じカウント**のフィガーを末尾に 1 件追加し、行を閉じる（`addFigure` 1 回＝元に戻す 1 回分）。打ったカウントは使わない（理由の行とボタンの文字で予告済み）。この時カウント欄は**赤くしない**（打った文字は使わないので、文字の誤りを責めない）。
   - 追加の行では**「同じ名前」がカウントの理由より先**（打ったカウントを捨てるのに「使えない文字」と言うのは矛盾するから）。順: 同じ名前 → カウントの問題（記号・先頭・並び）→ 名前が空。
   - 「複製して追加」の間、`check().valid` は **false**（閉じ方の原則では「無効＝捨てる」。別の行をタップして勝手に複製が増えない）。Enter でも何も起きない。
3. **編集の行（`open.kind==='edit'`）・名前を変えて仲間に入る時**（`fold(draft.name) ≠ fold(現在の名前)` かつ ほかの行と同じ名前。カウントも変えたかは問わない）:
   - 代表とカウントが同じなら普通の「決定」。
   - 違えば理由の行「同じ名前があります（1 2 & 3）」＋主ボタン **「カウントを合わせる」**（英 `Use that count`。アイコンなし。決定ではないので ✓ を付けない）。押すとカウント欄を代表のカウントにし、名前欄を代表の表記にそろえ、**行は開いたまま**（主ボタンは「決定」に戻る。先生がそろった値を見てから決定を押す）。その間 `valid` は false（閉じ方の原則で捨てる。Enter も効かない）。カウント欄が無効（記号・先頭・並び）の時はカウントの理由が先（Ruling 36 の順のまま）。順: カウントの問題 → 同じ名前 → 名前が空。
4. **編集の行・名前はそのままでカウントを変えた時**（`fold(draft.name) ＝ fold(現在の名前)` かつ 正規化後のカウントが現在と違う かつ 同じ名前の行がほかに N 件ある）:
   - `valid` は **true**（理由ではない）。理由の行の場所に予告の 1 行「**同じ名前の N 件も同じカウントになります**」（英 `The other N will change too`。見た目は `.dc-reason` と同じ＝`--warn-ink`・700・警告アイコン。ほかの行が変わるので注意の色で出す）。主ボタンは **「N+1 件まとめて決定」**（英 `Update all N+1`。アイコン `check`。自分を含めた件数）。
   - 押すと自分と同じ名前の全行のカウントを**1 回の `edits.update` で**変える（元に戻す 1 回分）。閉じ方の原則で閉じても同じ（有効＝確定＝まとめて変わる。予告の 1 行が出ているので Ruling 36 の代償の範囲内）。名前の表記はほかの行では触らない。
   - これが「1 つのフィガーのカウントを直したい時」の道。3. の向き（既存に合わせる）だけだと、2 回出てくるフィガーのカウントを直せず詰まる。
5. **古いデータ**（段5で受け取るかもしれない、同じ名前でカウントが食い違う列）: 開いて触るまで何もしない（同意）。判定は **draft が現在の値と違う時だけ**走る（名前もカウントも現在と同じなら 3.・4. のどちらにも入らない）。触ってカウントを変えれば 4. で仲間ごと直る。
6. **ボタンの数・主要操作数**: 主ボタンを替えるだけでボタンは増やさない。`[data-group="figure-form"]` は最大 10 のまま（U5）。S4 の期待値 5・7・7 は不変。`duplicateOpen()`（図形操作の「複製」）・`moveOpen()`・`previewOpen()` は `commitKeepingOpen()`／`check()` を通るので、2.・3. の無効状態では捨て、4. の状態ではまとめて確定してから動く（原則どおり）。
7. **型（`editor.ts`）**: `DraftReason` に `'sameName'` を足す。`DraftCheck` に `same?: { index: number; name: string; counts: string; others: number }`（代表の行と、自分以外で同じ名前の件数）と `action: 'add' | 'done' | 'addCopy' | 'matchCounts' | 'updateAll'` を足し、画面は `action` で主ボタンの文字・アイコン・押した時の処理を選ぶ（画面に判定を書かない）。`RoutineEditor` に `addCopy()`（2.）・`matchCounts()`（3.・draft を書き換えるだけ、`false` を返す）を足し、`close()` が 4. を含む（`action==='updateAll'` なら全行更新）。
8. **検査**: `test/app/routines/editor.test.ts` に: (a) 追加・同じ名前・カウント空 → `action='addCopy'`、`addCopy()` で代表の表記とカウントが末尾に入る・元に戻す 1 回、(b) 追加・同じ名前・カウント同じ → `'add'`、(c) 追加・同じ名前・カウント無効 → reason は `'sameName'`（カウントの理由より先）、(d) 編集・名前を変えて衝突 → `'matchCounts'`・`close()` は捨てる・`matchCounts()` 後は `'done'`、(e) 編集・名前そのまま・カウント変更・ほかに 2 件 → `'updateAll'`・`close()` で 3 行とも変わる・元に戻す 1 回で 3 行とも戻る、(f) 半角カナ・大小の違いは同じ名前、空白を含む名前は別、(g) 自分の index は除く（1 件だけなら衝突しない）。Playwright `smoke:routines` に 1 本: 「ウィスク 123」がある状態で追加の行に「ウィスク」→「複製して追加」が出て押すと 2 行目が「ウィスク 1 2 3」。実機確認表に 3 行: (1) 同じ名前を打つと「複製して追加」に変わり、押すと同じカウントで増える、(2) 2 回出てくるフィガーのカウントを 1 か所で変えると「3 件まとめて決定」で全部変わり「元に戻す」1 回で戻る、(3) 名前を既存の名前に打ち替えると「カウントを合わせる」→ 押すと欄がそろい「決定」に戻る。
9. **文言（`messages.ts`）**: `sameNameExists: '同じ名前があります（{counts}）' / 'Same name exists ({counts})'`、`addCopy: '複製して追加' / 'Add a copy'`、`matchCounts: 'カウントを合わせる' / 'Use that count'`、`othersWillChange: '同じ名前の{count}件も同じカウントになります' / 'The other {count} will change too'`、`updateAll: '{count}件まとめて決定' / 'Update all {count}'`。禁止語なし・依頼形なし。

**理由**: D13 の目的は「同じフィガーに別のカウントが紛れ込まない」こと。追加の行で「複製して追加」に替えるだけなら、名前を打った瞬間に同じカウントで足せるので、むしろ速くなる（カウントを打たなくてよい）。編集の行は向きが 2 つある。名前を変えて仲間に入るなら仲間が正しく、名前そのままでカウントを変えるなら先生の手元が正しい。向きを「名前を変えたか」で決めれば 1 文で説明でき、どちらの状態でも押せる主ボタンが必ず 1 つある（詰まらない）。主ボタンの文字を替えるだけにしたのは U5 の上限ちょうどだから。

**外れた時の代償**: 同じ名前で違うカウントを**わざと**使いたい時（短い版・長い版）は名前を分けるしかない（「ウィスク（短）」）。これは D13 が意図した制限。「N 件まとめて決定」は、別の行をタップして閉じても同じく全部変わる（予告の 1 行は出ている。元に戻す 1 回で戻る）。複製して追加は打ったカウントを捨てる（ボタンの文字で予告。わざと違う値にしたいなら上の名前分けへ）。名前の中の空白の有無は別の名前になる（候補の照合と同じ規則を優先）。

### D14 使える文字をいつも見せる

**決定**: 計画者の推奨に**同意**。具体値:
1. **常設の 1 行**: カウント欄の直下（`.dc-input--counts` の次の兄弟）に `<div class="dc-hint" id="{idPrefix}-hint">`。文言キー `allowedSymbols` を **`'使える文字：{symbols}'` / `'Allowed: {symbols}'`** に替える（全角コロン「：」・空白なし。ひとみうさの書いた形のまま。英語は半角コロン＋空白）。`{symbols}` は `allowedSymbols(danceId, locale)` で **日本語は「・」（U+30FB）区切り・空白なし**（`1・2・3・&`）、**英語は「 · 」（U+00B7・前後に空白）**（`1 · 2 · 3 · &`）。`@` は出さない（Ruling 38 のまま）。16px・**400**（見出しの 700 より軽く。読む物であって押す物ではない）・`--ink2`（白地 7.35）・アイコンなし・`margin-top: 6px`。追加の行・編集の行とも、空欄の時から出す。
2. **記号の誤り（`reason==='symbols'`）の時**: この常設の行を `.dc-hint.dc-hint--bad`（`--warn-ink`・700・先頭に `alert` アイコン）に変え、**文は同じ**（「使える文字：1・2・3・&」を 2 回出さない）。`.dc-reason` の行は出さない。欄は `.dc-input--bad`・`aria-invalid`。
3. **ほかの理由**（`leading`・`invalid`・`sameName`・`name`・`othersWillChange`）: 常設の行は `--ink2` のまま、**その下**に `.dc-reason` を出す（常設の行の位置を動かさない。「カウントの箱の下は使える文字」が常に同じ場所）。
4. **a11y**: カウント欄の `aria-describedby` は常に `{idPrefix}-hint`、理由が出ている時は `"{idPrefix}-hint {idPrefix}-reason"`。
5. **正規化に 1 字足す**（Ruling 38 の追記）: 案内に「・」を見せるので、`normalizeCounts` は空白・`|` に加えて **「・」（U+30FB）も除く**（半角「･」U+FF65 は NFKC で U+30FB になるので同時に吸収）。先生が案内どおり「1・2・3」と打っても通る。
6. **仕様・確認表の読み替え**: `design-skeleton.md` §4 S4 の「不正なら行を赤枠＋「使える記号: 1〜8, S, Q, &, a」の1行」→「カウント欄の下に常に「使える文字：＜種目の文字を・区切り＞」。文字の誤りはこの行が赤くなる（同じ文を 2 回出さない）。先頭・並び・同じ名前・名前が空はその下に理由の 1 行」。`stage3-device-check.md` の 3 行目の期待を「赤枠と、下の「使える文字：1・2・3・&」が赤くなる。「追加する」が押せない」に。Ruling 38 の「1行＝「使える記号: 」」は本 Ruling で置き換え。
7. **検査**: `counts.test.ts` に「・」の除去と `allowedSymbols('waltz','ja-JP')==='1・2・3・&'`・`('waltz','en')==='1 · 2 · 3 · &'`。Playwright: 開いた行に常設の行がある（空欄でも）、`12a3` で赤くなり `.dc-reason` が無い、`&123` で常設の行は灰のまま下に理由が出る。

**理由**: 「何を打てばいいか分からない」は、間違えてから教える設計の欠点そのもの。常に見せれば、誤りの時に同じ行を赤くするだけで済み、縦の高さも 1 行しか増えない。「文字」は「記号」より通じる（`S`・`Q` は記号ではないので実は正確でもある）。

**外れた時の代償**: 開いた行が 1 行（約 22px）高くなる。375px でチャチャチャの「1・2・3・4・&・a」（12 字）は 1 行に収まるが、パソドブレ「1・2・3・4・5・6・7・8・&」（17 字×16px≒272px）は欄の幅（約 300px）でぎりぎり（折れても許容。U10 の例外は不要）。「・」を打っても通るぶん、正規化の規則が 1 字増える（Ruling 38 の原則「トークンは変えない」の範囲内）。

**計画への反映（計画者）**: `editor.ts`（型・`addCopy`・`matchCounts`・`close` の全行更新）、`figure-names.ts`（`foldFigureName` export）、`counts.ts`（`allowedSymbols(danceId, locale)`・「・」除去）、`FigureForm.tsx`（常設の行・主ボタンの切替・`aria-describedby`）、`base.css`（`.dc-hint`・`.dc-hint--bad`）、`messages.ts`（文言 5 つ＋`allowedSymbols` の差し替え）、テスト（editor 7 件・counts 3 件・smoke 2 本）、実機確認表 3 行＋3 行目の書き換え、`design-skeleton.md` §4 S4。段3台帳に D13・D14 の行。

- **区切り**: 「・」（推奨。D14 の言葉どおり・文字同士が離れて見える）／空白「1 2 3 &」（今の形。短いが `&` が浮いて見える）。

## Ruling 51（D15）つかんだ行は指についてくる — 浮かせ方・影・自動スクロール中の位置・reduced-motion

前提: D15 で Ruling 49-5 の「行はその場に留まり、ゴーストは作らない」を取り消す（A 案）。ほかは Ruling 49 のまま（つかみ・8px・タップ扱い・自動スクロール・キーボード・挿入位置の線）。コードで確かめた事実: `useReorderDrag.ts` は `pointermove` ごとに `locate()` で**全行の `getBoundingClientRect()`** を取り `dropTargetFromY` に渡す（行を transform で動かすと、動かした行の矩形もずれて行き先の判定が壊れる）。`press` は押した点の `x`・`y`・`lastY` を持ち、スクロール量は持たない。`.dc-figures { position: relative }`（z-index なし）、固定の帯 `.dc-dock`・`.dc-tabs` は `z-index: 10`。`.dc-row` に背景色はなく、`.dc-row--now` が `--now-bg` を敷く。ドラッグ開始で試聴は止まる（Ruling 49-4）ので、動かす行が `--now` であることはない。

**決定**: 計画者の推奨に**同意**。足す・固定する点:

1. **動かすのはその行自身**（複製のゴーストは作らない。DOM は 1 つ）。`.dc-row--dragging { transform: translateY(var(--dy)); position: relative; z-index: 2; }`。`--dy` は**フックが毎 `pointermove`・毎フレームに行の `style` へ直接書く**（Preact の state を経由しない。state の `view` は今までどおり `from` と `lineTop` だけ。13 行の再描画を 60fps で起こさないため）。
2. **`dy` の式**: `dy = (指の clientY − 押した時の clientY) + (今の scrollY − ドラッグ開始時の scrollY)`。押した点を基準にする（ドラッグ開始の 8px で行が小さく跳ねるが、それが「持ち上がった」合図になる）。`press` に `scrollY0` を足し、`platform/viewport.ts` に `pageScrollY()` を足す（画面に触る面はこのファイルだけ、の原則のまま）。自動スクロールで `scrollPageBy` した後も同じ式で計算するので、ページが動いても行は指の下に留まる。
3. **行き先の判定は transform を無視する**: `locate()` で取った矩形のうち**動かしている行の矩形から `dy` を引く**（元の位置に戻す）。`dropTargetFromY` 自体は変えない（純粋関数のまま）。線の位置（`lineTop`）も元の位置の矩形で求める。これを忘れると、自分の矩形が指の下に来て常に「自分の前後」になる。
4. **範囲**: 計画者の推奨どおり**一覧の範囲に止める**。`dy` を `[list.top − row.top0, list.bottom − row.bottom0]` に clamp（`top0/bottom0`＝ドラッグ開始時の行の矩形を、スクロールぶん補正したもの。言い換えると行の上端が一覧の上端より上へ・下端が一覧の下端より下へ出ない）。末尾の「＋ フィガーを追加」と下固定の帯の上にかぶらない。指が範囲の外へ出ても行き先の判定（3.）は指の高さで続ける（先頭の前・末尾の後）。
5. **浮いた見た目**（`.dc-row--dragging`）: 背景 **`var(--surface)`（白。重なった下の行を透かさない）**、`box-shadow: 0 6px 16px rgba(20,33,61,0.25)`（`--ink` の色の影。`:root` に `--lift-shadow` として置く）、`border-radius: var(--r-s)`、下の罫線は `border-bottom-color: transparent`（浮いた札に線を乗せない）、今のネイビー 2px の `outline` は残す、`scale` はしない（文字がぼやけない）。つかみの ⠿ は `color: var(--primary)`。ほかの行は**動かさない**（詰める・空けるのアニメーションなし。§5「自動で動かさない」・U8）。挿入位置の 3px の線はそのまま。
6. **重なり順**: `.dc-figures { isolation: isolate }` を足し、行の `z-index: 2` を一覧の中に閉じ込める（固定の帯の 10 と競わない。帯の下を通る時は帯が上）。
7. **transition・reduced-motion**: 指の動きそのものなので **transition は付けない**。`prefers-reduced-motion` でも同じ（U8 の 300ms・自動の動きの対象外。動かしているのは利用者）。落とした瞬間・中断（`pointercancel`・Esc・blur・visibilitychange）の瞬間に `--dy`・クラスを外し、並べ替え後の位置に描き直す（着地のアニメーションなし。線が消え番号が変わるで足りる）。
8. **マウス**: 同じ経路（Pointer Events）。`body` の `cursor: grabbing` はそのまま。
9. **検査**:

**理由**: 「掴んでる感じが薄い」は、行が指から離れて留まるから。行自身を動かせば DOM も履歴も今のまま（`move(from,to)` 1 回）で、増えるのは `--dy` の計算と矩形の補正だけ。ゴースト要素を作ると見た目の二重管理（文字・幅・`--now`）が増えるので採らない。範囲を一覧に止めるのは、固定の帯や追加ボタンの上に行が乗ると「そこに落ちる」と誤解させるため。

**外れた時の代償**: 動かしている行が下の行に重なって一時的に隠す（影と枠で「浮いている」と分かる。行き先は線で示す）。clamp のぶん、指が一覧の外にある間は行が指から離れる（先頭の前・末尾の後は線で分かる）。transform を毎フレーム直接書くので、Preact の描画規則の例外が 1 か所増える（コメントで明記）。
