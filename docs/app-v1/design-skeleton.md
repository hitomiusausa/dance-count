### 生徒の最短経路（タップ数）
- 初回: S1 の種目タイル（1）→ S2 の ▶（2）＝ **2タップで音が出る**。
- 2回目以降: S1 最上段「前回: ワルツ ▶」（1）＝ **1タップ**（再生画面へ遷移し即再生。iOS の音声ロック解除はこのタップ内で行う）。
- ルーティン: 「ルーティン」タブ（1）→ カード（2）→ ▶（3）。

### 先生側の入口の分け方
- ホーム S1 に「先生の声で練習」カード（横幅いっぱい・56〜64px・マイクのアイコン＋文字＋山形）を**種目タイルの上**に置き、タップで S7（声の一覧。録音・受け取るの2ボタンを含む）へ直行（D1・Ruling 16）。設定タブにも見出し「先生の方へ」を立て、「自分の声を録音する」「ルーティンを配る」の2項目を残す。
- 戻る／下タブの出し分けは Ruling 17: ルート（S1・S3・S6）と一覧（S7・S12・S13）は下タブ表示、集中画面（S2・S4・S5・S8〜S11）は下タブを隠し左上に「‹ 戻る」（48px・文字ラベル必須）。ブラウザの戻ると同じ動き。
- 録音完了画面（S8 の最後）から直接 S9「配る」へ行ける（先生の一連の作業が一本道）。

### 初回起動時の体験
1. 言語は端末言語で自動決定（`resolveUiLocale`）。S1 右上に地球アイコン＋「日本語 / English」（タップで即切替。設定にも同じ項目）。
2. チュートリアル・ウォークスルーは**出さない**。S1 の見出しが「種目を選んでください」の1行で説明を兼ねる。
3. 初めて再生に成功した後、S1 の最下段に1回だけ「ホーム画面に追加すると、アプリのように使えます →」カード（閉じたら二度と出さない。S6 からいつでも読める）。
4. マイク・保存の許可は初回起動では一切求めない（録音・保存の直前だけ）。

## 2. 各画面の役割・載せるもの・載せないもの

### S1 ホーム
- 載せる（上から）: 「前回: ○○ ▶」カード（2回目以降）、「先生の声で練習」カード（Ruling 16）、見出し「種目を選んでください」、10種目のタイル（2列×5行、1行 64〜72px。各タイルは種目名＋拍子の小さな副題「3拍子」「4拍子」）、右上に言語切替（`data-utility`）。
- 機械判定: 375×667（タブバー込み）の初期表示に「先生の声」カードと10種目すべてが入ること。主要操作数＝3（前回カード・先生の声・種目タイル群。Ruling 18）。
- 載せない: ルーティン、声の選択、速さ、注意書き、録音ボタンそのもの（カードは S7 への入口のみ）。
- 段階的開示: なし（ここは選ぶだけ）。

### S2 再生（基本カウント）
- 載せる（初期表示、Ruling 18 の主要操作 5 ちょうど）: 左上「‹ 戻る」（`data-back`、Ruling 17）、種目名（見出し）、**大きな現在カウント表示**（64px 以上、鳴っている語をそのまま文字で。鳴っている拍だけ琥珀色＝D8）、小節内の拍インジケータ（操作ではない）、速さ3択（`data-group`。ゆっくり／標準／速め。選択中に ♩=84 を併記）、メトロノーム・はじめの合図（アイコン＋ラベルの大型トグル。Ruling 19）、「声: 標準（英語）」チップ（初期値は UI 言語に関わらず英語＝D3）、画面下固定の ▶ 再生／■ 停止（72px）。下タブは隠す。
- 「くわしく」（折りたたみ、`summary[data-more]`、1画面に1つ）: カウントの型（複数テンプレートの種目のみ: ワルツ `1 2 3` / `1 2 & 3`、クイック `S Q Q` / `Q Q S` 等。初期値 `templates[0]`、種目ごとに記憶。Ruling 18）、速さスライダー（40〜220）、競技の速さ（範囲内の値）、繰り返しオフ（初期オン）、声のタイミング微調整（±200ms・声のパックに保存）、Bluetooth 補正つまみ（後段でよい）、［第2弾］「曲に合わせる」（Ruling 20。v1 では出さない）。
- 載せない: ルーティン切替、録音、ファイル操作、監修に関する注意文。
- 再生中: 停止以外の操作を触っても音が途切れないものだけ即反映（速さ・メトロノーム・声は停止→適用→再開を内部で行う。ユーザーには「反映されました」等の文言を出さない）。

### S3 ルーティン一覧
- 載せる: 「＋ 新しいルーティン」（横幅いっぱい、空でも同位置）、ルーティンカード（名前・種目・フィガー数・▶）、受け取ったルーティンには「○○さんから」の副題。
- 載せない: 旧24本、provenance 表示、レビュー状態。
- 段階的開示: カードをタップで ▶ と「編集」「配る」「削除」が展開（前回設計の B 方式を踏襲）。

### S4 ルーティン編集
- 載せる: 名前、種目（変更は空のときだけ）、フィガー行（番号・名前・カウント・▶ 試聴）、行の並べ替え（↑↓ボタン。ドラッグは補助）、末尾の「＋ フィガーを追加」、Undo/Redo、下固定の「全体を試聴」。
- フィガー追加の入力: 名前（追加の行で名前が空の間は、名前の欄の下にその種目の照合済みフィガー全部をボタンで並べる＝見出し「ワルツのフィガー（17）」・定義順・verified のみ・VW は無し。タップで名前に入る。その間カウントの欄・使える文字・カウントの形は出さず、名前が入ると同じ所に出る。1 文字以上打てば今までの候補（最大 5）。ひらがなとカタカナは同じ名前として照合する。Ruling 3・54）、カウント（「カウントの形」ボタン群＝`countPatterns(danceId)`。プロファイルの数から規則で作る形・最大 8・`templates` が先頭・名前では変わらない。Ruling 53 ＋手入力。パーサで即検証し、不正なら行を赤枠。カウント欄の下に常に「使える文字：＜種目の文字を・区切り＞」。文字の誤りはこの行が赤くなる（同じ文を 2 回出さない）。先頭・並び・同じ名前・名前が空はその下に理由の 1 行。Ruling 38・50）。同じ名前のフィガーは同じカウント（Ruling 50 D13: 追加で同じ名前なら「複製して追加」、名前を既存に打ち替えたら「カウントを合わせる」、名前そのままでカウントを変えたら「N+1 件まとめて決定」）。同じ名前の注意は名前の欄のすぐ下に出す。追加の行で同じ名前になった時は（カウントが同じでも。切り替えは名前だけ）「複製専用の形」＝名前の欄の下に「同じ名前があります：＜代表の名前＞（＜代表のカウント＞）」と「名前を変えると、違うカウントにできます」、カウントの欄・使える文字・カウントの形は出さず、主ボタンは「＜代表のカウント＞ で複製して追加」。名前を変えて同じ名前でなくなれば、打っていたカウントのまま元の形に戻る（D19）。画面のキーボードが開いている間は下の帯（「▶ 全体を試聴」）を出さない（iOS 26 が帯をキーボードの上へ持ち上げて欄を覆うため。開いているかはフォーカスでなく見えている高さで決める＝レイアウトの高さ − visualViewport の高さ ＞ 150px、`lib/keyboard.ts`。閉じると戻る。PC・visualViewport の無い環境では隠さない）。複製の形の間、名前の欄を打っていれば主ボタンをキーボードの上へスクロールする（見えている範囲の変化のたびにやり直す。D19・F6）。
- 小節の注意（D16・Ruling 52）: ワルツ・ヴィエニーズワルツで 3 拍の倍数でないフィガーは、行に「3拍のカウントではありません」（閉じた行の最初の 1 件だけ「必要なら編集してください。」つき。開いている行は入力欄の下に短い形）。全種目でルーティンが小節の途中で終わる時は一覧の下に 1 行「小節の途中で終わっています。繰り返すと頭がずれます。」。どちらも止めない（入力・保存・再生はそのまま）。
- 「くわしく」: はじめの合図の小節数、速さ指定（空なら種目標準）、声のタイミング微調整、元に戻す。
- 載せない: 旧カタログ由来の候補カウント、reviewStatus 編集。

### S5 ルーティン再生
- S2 と同じ骨格。追加: フィガー一覧（鳴っている行がハイライト・自動スクロール）、範囲（開始・終了フィガー）は「くわしく」へ。注意文「このルーティンはあなた（または○○さん）が作ったものです」を見出し下に1行（監修済みと誤認させないため。Ruling 8）。

### S6 設定
- 載せる: 言語、声（S7 へ）、ホーム画面に追加する方法、音が鳴らない時、先生の方へ（録音・配る）、プライバシー／アプリについて（バージョン表示）。
- 載せない: 開発者向け項目、キャッシュ操作。「データを全て消す」はプライバシー画面の最下部に。

### S7 声
- 載せる: 「標準の声（英語）」「標準の声（日本語）」「○○さんの声（受け取った）」「自分の声（録音中 7/12）」をラジオ風の大型リストで。選択中に ▶ 試聴（ワルツ1小節）。下に「ファイルから受け取る」「自分の声を録音する」。
- 受け取った／自分の声の行を展開: 「配る」「ファイルに保存」「削除」。

### S8 自分の声を録音（ウィザード）
- 0: 説明画面（何を録るか・端末内保存・削除可）→「録音をはじめる」でマイク許可（Ruling 8）。
- 1〜12: 1画面1語。見出しに語（「スロー」「1」…）、進み具合 3/12、大きな録音ボタン（押している間ではなく、押す→1.5秒録る→自動停止。もう一度押すと録り直し）、自動頭出し後の波形ミニ表示と ▶ 聞く、「次へ」。
- 13: 完成。ワルツで試聴（標準の声との聞き比べボタン）、名前入力（既定「○○の声」）、「配る」「あとで」。
- 載せない: ゲイン・onset の数値、mimeType、正規化のオン／オフ。

### S9 配る
- 名前（先生名）、同意チェック1つ、「ファイルを作る」。作成後: 共有シート（可能なら）か保存。同じ画面に「生徒への案内文（コピー）」ボタン: iPhone/Android それぞれの受け取り手順入りの定型文（§4）。
- ルーティンも同梱する場合は「一緒に配るルーティン」をチェックリストで選ぶ（0件可）。

### S10 受け取る
- 1画面: 「ファイルを選ぶ」大ボタン、iPhone 向け図解（LINE → 共有 → "ファイル"に保存 → ここで選ぶ）。選んだ後: 中身の確認（「○○さんの声・日本語・12/12」「ルーティン 2本」）→「使う」。同名パックがあれば「置き換える／両方残す」。

## 3. データモデルの変更点

### 保存先（Ruling 11）
- IndexedDB `dance-count-v2`: version 1 → 2。既存 `voice-packs` を維持し `routines`・`settings` を追加。localStorage の `dance-count-v2-routine-draft:*` と `dance-count-v2-ui-locale` は**読み取り互換**（初回起動時に移行して消す）。

### ルーティン（既存形式を拡張。既存キーは変えない）
```
{ id, danceId, name, bpm|null, countInBars, source, status,
  figures:[{id, name, counts}],
  provenance:{ sourceKind:'user-created'|'received', authority:null, authorityClaimStatus:'none', reviewStatus:'unreviewed' },
  receivedFrom?: { distributor, receivedAt },
  createdWith:{ app:'dance-count', version },
  updatedAt }
```
- `counts` の文字列とパーサトークンは変更しない（AGENTS.md）。
- 旧 24 本は読み込まない（`source:'legacy-import'` は受理しない。開発用ツールのみ）。

### 声のパック
- 端末内: 既存 `recorded-voice-pack` schemaVersion 1 のまま（Blob＋onsetMs 等）。追加フィールド `origin:'recorded'|'received'`, `distributor?`, `consent?`（下）。
- 標準音声: manifest schemaVersion 2（英既存、日本語を Ruling 5 で追加）。

### 配布ファイル（Ruling 4）
```
{ schemaVersion:1, type:'dance-count-bundle',
  createdAt, createdWith:{app,version},
  distributor:{ name },
  consent:{ voiceDistribution:true, consentedAt },
  voicePack?: <exportRecordedVoicePack() の出力（schemaVersion 1, type 'dance-count-recorded-voice-pack', words.*.dataBase64）>,
  routines?: [ <ルーティン（Blob なし）> ] }
```
- 読み込みの受理: `dance-count-bundle` ／ 単体 `dance-count-recorded-voice-pack`（既存書き出し）の両方。未知の `schemaVersion` は「新しいアプリで作られたファイルです。アプリを更新してください」（§7）。
- 検証は既存 `validateRecordedVoicePack` と `rhythm-parser` によるコンパイルで行い、1フィガーでもパース不能なら**そのルーティンだけ**除外して理由を表示（声は取り込む）。

### 設定
`{ uiLocale, voiceLocale:'en'（初期値は UI 言語に関わらず英語＝D3）, selectedVoiceId, lastDanceId, lastTemplateByDance:{}, speedPresetByDance:{}, metronome:true, countInBars:1, loop:true, hints:{homeScreenCardDismissed, wakeLockTipShown} }`

### 曲を載せる口（Ruling 20、v1 は型と写像のみ）
- `TempoMap`: `tickToMs(tick)` / `msToTick(ms)`。実装は `constantTempo(bpm)`（現行計算と同値）と `beatMapTempo(beatsMs[], beatsPerBar)`（拍時刻の区分線形補間）。エンジン・表示の「tick → 秒」はこの1箇所に集約し、第2の時間計算を作らない。
- `TrackProfile { id, danceId, title, file, durationMs, beatsPerBar, tempo:{kind:'constant', bpm, firstBeatMs}|{kind:'beatMap', beatsMs:number[]}, license:{kind:'CC0'|'PD-recording'|'CC-BY', source, url, note}, measuredAt }`。v1 に実データは入れない。練習セッション状態に `track:null` を予約。
- 第2弾で作る: 曲の音の再生（tick 0 を `firstBeatMs` に合わせて開始）、S2「くわしく」の「曲に合わせる」、同梱音源とライセンス台帳、`tools/measure-track-beats.js`。曲ありのときは速さ3択を無効（タイムストレッチなし）。ユーザー自身の曲の読み込みは範囲外（D7）。

## 4. 配る・受け取るの手順

### 先生側
1. S8 で 12 語を録音 → 完成画面「配る」（または S7 の自分の声 → 配る）。
2. S9 で名前と同意 → 「ファイルを作る」。
3. 共有シートが出る端末（iPhone・Android）: LINE／メール／AirDrop を選ぶ。出ない端末（PC・古いブラウザ）: ダウンロードされたファイルを LINE/メールに添付。
4. 「生徒への案内文（コピー）」を押し、LINE のメッセージに貼って送る。

### 生徒側
- **iPhone（ホーム画面アプリ／Safari）**: LINE の添付をタップ → プレビュー右上の共有 → 「"ファイル"に保存」→ アプリを開く → 設定 → 声 → ファイルから受け取る → 「ファイルを選ぶ」→ 最近使った項目／iCloud Drive から選ぶ → 「使う」。詰まりどころ: (a) LINE から直接アプリへ渡せない（iOS に共有ターゲットがない）(b) ホーム画面アプリで「ファイルを選ぶ」が開かない報告（F3）→ 開かない時は「Safari で開いて受け取る」リンクを同画面に出す (c) 保存先を覚えていない → 「最近使った項目」を最初に案内（iOS 26.3 の Files のタブ名。段5で確認）。
- **Android（Chrome PWA）**: LINE の添付 → 共有 → アプリ名を選ぶ（share_target）→ S10 に直接届く → 「使う」。詰まりどころ: PWA を入れていないと共有先に出ない → フォールバックは iPhone と同じ「ダウンロード → ファイルを選ぶ」。
- **PC**: メールの添付を保存 → ブラウザでアプリ → 設定 → 声 → ファイルから受け取る → ファイル選択。詰まりどころ: 受け取った後、PC で練習することは少ないので「スマホで受け取るのが便利」の一言を案内文に入れる。
- 案内文（定型・日英）は上の手順を箇条書きにしたもの。アプリ内にも同じ図解（S10）。

## 5. 音声まわりの方針

- 標準音声: 英語 `default-en-female-v1`（既存）＋ 日本語 `default-ja-female-v1`（Ruling 5 のゲート通過後）。どちらも manifest の onsetMs 実測済みであること。
- 言語の独立: UI 言語と声の言語は別設定（Ruling 12）。カウント語彙は `count-vocabularies` の voice key（12語）で、tick・フィガー ID・トークンは翻訳で変えない。
- タイムライン: メトロノーム・声・ハイライトは `rhythm-compiler` の整数 tick から導く唯一の計算。tick → 秒の変換は `tempo-map.js` の1箇所（v1 は `constantTempo` のみ稼働、Ruling 20）。表示側は `audioContext.currentTime`（＋取得できれば `outputLatency`）で tick を読む。
- iOS（Ruling 6）: `audioSession.type='playback'`／タップ内での AudioContext 生成＋resume＋無音再生／`statechange` と `visibilitychange` の監視／WakeLock 取得と再取得／鳴らない時のバナー＋S11。
- Bluetooth: 自動補正なし。ハイライトにのみ outputLatency を加算。手動つまみは後段。
- 実機確認（ひとみうさの iPhone）: マナーモードで鳴る／ロック→復帰で ▶ 再押しの案内が出る／AirPods で声とメトロノームがずれない／ホーム画面起動で音と WakeLock／ファイルを選ぶが開く。

## 6. 技術構成（Ruling 1）

- ディレクトリ:
  - `src/engine/`（旧 `src/v2` の全 .js を無改変で移動。`?v=` を剥がすのみ。加えて新規 `tempo-map.js`＝Ruling 20）、`test/engine/`（旧 `test/v2`。import パスだけ追従。`tempo-map.test.js` 追加）
  - `src/app/`（Preact＋TS。`screens/` `components/` `state/` `platform/` `i18n/`）
  - `src/app/platform/`: `audio-context.ts` `recorder.ts` `storage.ts`（IndexedDB）`files.ts`（share/download/pick）`wake-lock.ts`。Capacitor 化ではここだけ差し替える
  - `public/audio/`（標準音声）、`legacy/`（旧 public。開発用ページ）
- テスト維持: `npm test` = `node --test test/engine/*.test.js`（既存89件＋新規）。`html-module-syntax.test.js`・`ui-assets.test.js` は `legacy/` を見るように修正。`timing:audit` の出力を移設前に保存し、移設後に diff ゼロを完了条件にする。UI は Playwright（`ui:check` 移植＋Ruling 7 の判定追加）。
- 公開先（D4）: 所有ドメイン dancemap.jp のサブドメイン（例 count.dancemap.jp）。配信基盤・DNS は公開直前に確認し、設定前に改めて許可を取る。アプリ名は「Dance Count」、manifest の `short_name` も "Dance Count"、副題 "for Ballroom" は見出しのみ（D2）。運営者表記は くうが株式会社（D5）。
- PWA キャッシュ戦略: アプリ本体（JS/CSS/HTML/アイコン）は precache（ハッシュ名・更新は新 SW で差し替え、「新しい版があります・再読み込み」バナー）。標準音声 wav は precache に含める（合計 数MB 以内。超えるなら初回再生時に runtime cache・CacheFirst）。ユーザーデータは IndexedDB で SW の対象外。`voice-pack-loader` の `no-store` は撤去。
- ストアに包む前提: ルートは相対（`base:'./'`）、ルーティングはハッシュかメモリ内（ディープリンク不要）、サーバー API ゼロ、`platform/` 以外で `window`/`navigator` を直接参照しない（lint ルールで禁止）、manifest に `share_target`（Android）。
- 言語: `ui-messages.js` の en/ja-JP を `src/app/i18n/` に移し、キー一致テスト（既存 `ui-messages-keys.test.js`）と禁止語テスト（Ruling 7）を掛ける。`DANCE_NAMES` は既に日英あり（`dance-profiles` の日本語名は表示に使わない）。

## 7. エラーと例外時の画面

共通規則: 1画面＝何が起きたか1文＋次に押すボタン1〜2個。技術用語・コード番号なし。文言は日英。

| 状況 | 画面 |
|---|---|
| マイク拒否 | S8 内「マイクが使えない設定になっています」＋「設定の開き方」（iOS: 設定 → Safari またはアプリ名 → マイク）＋「あとで」 |
| マイク非対応ブラウザ | 「このブラウザでは録音できません。Safari（iPhone）か Chrome で開いてください」 |
| 録音が無音／短すぎ | その語の画面で「声が入っていませんでした。もう一度」（自動判定: onset 検出不能） |
| 保存領域なし／保存失敗 | 「保存できませんでした。空き容量を確認してください」＋「ファイルに保存」（メモリ上の内容を逃がす） |
| 壊れたファイル／別の種類のファイル | S10 内「このファイルは読めませんでした。先生に送り直してもらってください」＋ファイル名表示 |
| 新しすぎる schemaVersion | 「新しいアプリで作られたファイルです。アプリを更新してください」＋「更新する」 |
| 一部のルーティンが不正 | 取り込み結果に「ルーティン『○○』は読めませんでした」を列挙。声は取り込む |
| 音が鳴らない（2秒判定） | S2 上部バナー「音が出ない時は…」→ S11（マナーモード・音量・イヤホン・もう一度 ▶） |
| AudioContext が中断（電話・ロック復帰） | 再生停止・▶ を点滅させず「もう一度 ▶ を押してください」の1行 |
| WakeLock 不可 | 1回だけの案内（Ruling 6-3） |
| オフラインで標準音声未キャッシュ | 「この声はまだ端末に入っていません。インターネットに接続して一度再生してください」 |
| 共有シートが使えない | ダウンロードに切替（案内不要。ファイル名を表示） |

## 9. 見た目の方向決め（比較 HTML 用の定義）

**決定済み（D8）: B「Studio Navy」**。比較 HTML は `docs/app-v1/mockups/b-studio-navy.html`（a・c・index も同フォルダ）。清書時の差し替え: モックの S2 トグル「繰り返す」→「はじめの合図」（Ruling 19）、S1 の「先生の声で練習」カードを種目タイルの上へ（Ruling 16）、S2 左上に「‹ 戻る」（Ruling 17）。以下は比較時の定義（記録として残す）。

前提: 前回決定（青×白継承・SVG 線画アイコン・絵文字禁止・アイコン＋短いラベル）を尊重し、3案とも**明るい背景**。却下済みのクリーム系・黒×金は再提案しない。比較に使う画面は **S2 生徒の再生画面** と **S8 先生の録音画面（1語分）**。PC 幅 1280 と 375 の両方で、同じデータ（ワルツ・♩=84・3拍目ハイライト／「スロー」3/12）。

| 案 | 狙い | 配色の考え方 | 書体 | 密度 |
|---|---|---|---|---|
| A「Clear Blue」（継承・大型化） | 今の青×白をそのまま大きく・太く。既存ユーザーに連続性 | 背景 淡青グレー、カード白、主要アクション 青、文字 濃紺。アクセントは青1色 | システム書体（SF / Hiragino / Roboto）。数字は太字 | 低。カード間 16px、ボタン 56/72px |
