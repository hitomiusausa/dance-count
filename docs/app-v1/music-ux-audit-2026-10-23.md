# 音楽練習 UX・設計監査（2026-10-23）

担当: Astra。対象: `agent/music-practice-20261023`の未commit実装、`http://127.0.0.1:5195/`の開発preview。監査中にうさこが修正し、以下は初回指摘と再確認を分けた記録。監査担当はコードを変更していない。

## 結論

「使う」→音楽→曲→大きな再生の導線は明快。独立Chromeで初回操作と短画面を確認し、詳細を開いても主要操作は7群（上限9）、通常は3群（上限5）。重大なデータ破壊や誤った「保存完了」は確認しなかった。初回には保存失敗の誤案内、作成中ボタンの無反応、音量変更での再生停止があり、うさこへ伝えて修正が進んだ。

本監査はローカルpreviewのUX確認。音程維持品質、全曲の拍正解、販売権利、公開ビルド、実機受入を合格とするものではない。

## 確認方法と契約

- Playwright CLIの独立session `music-ux-astra`。親の`music-app`には触れていない。
- 日本語375×548、250×445。英語375×548、250×445。スクリーンショットとcomputed rect／文字サイズ、遷移・再生・中止を照合。
- `MusicScreen.tsx`、Home、router、music preferences/provider/export、Session、音楽plan/engine、関連CSSを確認。
- 根拠: [既存仕様§5〜6](../superpowers/specs/2026-10-11-app-v1-design.md)、[役割分け確認の§5b](role-split-usability-walk.md)、[音楽実装設計図](../superpowers/plans/2026-10-23-music-practice-implementation.md)。本文18px・補助16px、tap48×48px／間隔8px、▶■72pxかつ幅60%以上、操作数初期5／全体9以下、詳細1つ、文字付きの戻る。
- 原因再現には独立ブラウザ内だけで音楽取得を1,800ms遅延。中止後の遅い完了が保存ボタンを復活させないことを確認。mockは解除済み。

## 指摘と対応

### MUX-01 / P1 — 長さ制限でも「音を小さく」と誤案内

**再現済み。** 後半・4回・ゆっくり・合図オン→音声ファイルを作る。1区間29.1462585秒×4＋合図で120秒を越え、`renderMusicFile`が長さで拒否するのに「音を小さくして」と出る。音量を下げても解決しない。

原因: `makeFile`のcatchが全失敗を同じ文言へ変換。修正案: 長さ／音割れ／通信等の理由を分け、作る前に合図込み秒数と容量を表示。長すぎる場合は回数を減らす案内で開始を止める。

対応: `MusicFileError`の理由別処理、事前見積り、120秒超disabledの実装をコードで確認。最終実画面の再確認は下記追記に記録する。初回証拠: `output/playwright/music-ux-astra-wrong-error.png`。

### MUX-02 / P2 — ファイル作成中の「再生」が押せるように見えて無反応

初回コードでは`toggle`がrendering時にreturnするだけ。利用者には何も起きないように見える。設定準備中も同じ。

対応・**再確認済み**: dockを「音声ファイルを作っています…」＋disabledへ変更。取得を遅延させた実画面で、ラベル一致・disabled=true・「やめる」1つを確認。通常の準備中は準備ラベルを使う。戻るは使える。

### MUX-03 / P2 — 音量を触るたび音が止まる

原因: 音量と速度／区間が同じ`change`を通り、`session.stop()`する。聞きながら音量を合わせられない。

対応・**再確認済み**: gain更新用経路に分離。実際の再生中に音楽sliderをArrowLeftで変更し、`data-playing`がtrue→trueのままを確認。出力済みFileは音量変更時に破棄され、古い設定のファイルを保存しない構造も確認。

### MUX-04 / P2 — 16pxの説明段落が既存本文契約に反する

初回`p.dc-music-note`はcomputed16px。U1ではpは本文18px以上。保存結果まで小さい補助扱いになっていた。

対応: 補助説明をdiv16px、結果statusを本文18pxへ分離。コードとDOMの再確認済み。見積り・案内の文字を縮めて詰め込まない。

### MUX-05 / P2 — 前回ありの短画面でHomeの音楽入口が下タブに隠れる

**再現済み。** 375×548、既存基本ルンバを一度開いてから使うへ戻る。前回カードありでは入口y436〜492、固定下タブ開始y480で下12pxが隠れる。初回はy372〜428で全体が見える。

修正案: 短画面だけ音楽入口の上余白24→12px。既存10種目タイルを縮小せず、スクロール可能性も維持する。

対応: media queryでmargin-top12pxをコード確認。最終rectは追記に記録。初回証拠: `output/playwright/music-ux-astra-home-resume.png`。

### MUX-06 / P2 — 未知曲IDが失敗画面と無効URLに残る

**再現済み。** `#/use/music/unknown-song`でcatalog取得成功後も、無効hash＋失敗文のまま。設計では曲一覧へ置換する。通信失敗と「曲が存在しない」を同じにしない。

対応: `tracks!==null && !failed && !track`だけU3へ`replaceRoute`する処理をコード確認。最終遷移は追記に記録。

### MUX-07 / P3 — 選択速度の見た目が色差だけ

初回はaria-checkedはあるが、見た目は背景色のみ。既存SpeedChoicesはcheck印を併用している。

対応: 選択速度にcheck iconを加えたコードを確認。文字ラベルとaria-checkedを維持。これによる幅増加を短画面で再確認する。

### MUX-08 / P2 — 短画面で「くわしく」が再生バーの裏にある

区間要約追加後、英語375×548ではMore options y464〜512、Play y464〜536。詳細へスクロールすれば届くが、初期画面には存在が見えない。250×445では速度欄の途中までがdockに隠れる（拡大時は縦scrollを許容する既存方針）。

修正案: 要約余白と速度3択の配置を調整し、375×548では少なくとも詳細の存在が分かるようにする。tap48px／本文サイズを犠牲にしない。250pxは横はみ出し・語の切れ・縦scroll到達を守る。

### MUX-09 / P3 — ページが隠れて作成中止した時の理由が残らない

**コードからの指摘、実機未確認。** `onPageHidden`はabortするが、abortされたcatchはfileStatusを更新しない。別アプリから戻ると、作成が消えた理由が分からない可能性がある。

修正案: ユーザーの「やめる」と同様に中止statusを残す。戻っても自動で再生成しない。電話・画面lockは実機受入に含める。

## 良好だった点

- 初回Homeから曲選択まで入口が1つ。試作であることを一覧にも表示し、販売済み・審査済みとは言っていない。
- 375pxで再生幅343px・高さ72px。戻る48px、速度48px、声48px。250pxでも横scrollWidth250で横はみ出しなし。
- 詳細開は7操作群。選択肢は種目を増やしても一覧の区分へ移す余地がある。現在の1曲での操作数を30曲時の保証にはしない。
- 曲や設定を変えると作成済みFileを無効化。受け取った声の無条件出力を防ぐ。生成完了後の「保存する」は別タップで、まだ保存していないのに「保存済み」と表示しない。
- 作成→やめる→遅い取得完了を待つと、保存ボタン0、中止の案内、再生ラベルが戻ることを確認。
- 独立sessionのconsole error／warningは0（監査時点）。

ひちゃんの追加希望で「はじめの合図」のclick switchを、**始める順番＋あとから入るまで**の1群へ置換。曲先2小節を既定にし、曲を聞く間の表示も追加。全体は初期4群／詳細8群のまま。曲先は音楽を進め続けて声だけ待つ。声先は実際の声が先に鳴り、曲の拍位相へ続く。6通りの開始をブラウザで、16保存WAV・816語を波形で確認した。音楽そのものの拍・小節頭は未監修。
