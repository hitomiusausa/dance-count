- 冷えた開発サーバーで Preact の読み込みが途中で再最適化される問題は `vite.config.ts` の `optimizeDeps.include` で解決済み。設定を消さないこと

- 実機・シミュレーターで確かめる前はページを再読み込み（`?r=<時刻>` を付けると確実）。古いコードが残っていて、直したはずの見え方や文言の鍵がそのまま出ることがある

- **WebKit は `audioSession.type='playback'` のままだとマイクを開けない**（`InvalidStateError: AudioSession category is not compatible with audio capture.`。iOS 26.3 のシミュレーターでも確認）。アプリは起動時に `playback` を書く（マナーモード対策）ので、録音は必ず `platform/recorder.ts` の `recordTake`／`requestMicrophone` から（中で `withRecordingSession` を通す。参照カウントなので重なっても壊れない）。画面から `getUserMedia` を直接呼ばない
- **Playwright の WebKit は `permissions: ['microphone']` を知らない**（`Unknown permission`）＝WebKit で録音の自動検査はできない。WebKit で見られるのは `ui-state` の表示だけ。デスクトップの WebKit は mp4 の decode に失敗する（iOS の代わりにならない）

- `word-break: auto-phrase` は Chrome だけ。iOS Safari では「録音できませ／ん。」「も／う一度」のように語の途中で折れることがある（通し確認で「好み」。手動の改行は入れない＝折り返しは幅から診断）
- **headless の Chrome は `.txt` の `navigator.share` を出せず、promise が永遠に終わらない**（ui:check は `navigator.share` を即解決の偽物に、スモークは `canShare=false` にしてダウンロードに落とす）。`.json` は Chrome が `share()` で拒む（`NotAllowedError`。`canShare` は通す＝F19・F20。だから D36 で `.txt`）

- **配布ファイルの形を変えたら `npm run fixtures:share`（`node tools/make-share-fixtures.js`）で固定ファイルを作り直す**（`test/app/share/fixtures.test.ts` が落ちて知らせる）

- **段3からの「seed 直後の S4 待ちで 30 秒切れ」の正体は検査の手順**（段7 Task 1 で計測）: seed はアプリの裏で IndexedDB に書くのに、検査が続けて `page.goto(<同じ文書のハッシュ>)` をすると、動いているアプリはメモリの古い一覧（seed の前＝空）で知らないルーティンの S4／S5 を S3 へ置き換え、直後の `reload()` が置き換わった URL を読む。**seed の後に画面を開く時は必ず `openAfterSeed`（`tools/ui-check-routines.js`。`about:blank` を挟んで新しく読み込む）**。直した後は 12 並行 × 24 回で 0 回。アプリの作り（知らない ID は S3 へ）は正しい。`smoke:practice` の「ui:check の直後に 1 回だけ G1 が落ちる」は seed を使わないので**別の揺れ**で、未再現のまま（段7の間は一度も出ていない。続くなら S2 を開いた時の声の解決と即再生の順を疑う）
- **dev（`npm run dev`）には Service Worker が無い**。SW・オフライン・更新の帯の本物・share_target は公開ビルド（`smoke:pwa`・`vite preview`・`serve-dist`）でしか見えない。帯の見た目だけなら `?ui-state=update-ready`
- precache の照合は既定で `?v=` を無視しない。`src/sw.ts` の `IGNORED_QUERY` から `/^v$/` を消すとオフラインで `six.wav` が鳴らない（`smoke:pwa` が落ちる）
