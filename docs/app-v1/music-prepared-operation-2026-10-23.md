# 準備した曲で使う運用と、利用者の画面

入口の最新構成は[音楽の3入口](./music-navigation-2026-10-23.md)（D63）を参照。以下は運用の基本と当時の接続記録。

2026-10-23 ひちゃんの承認: 曲はこちらで仕上げ、利用者には波形や解析操作を見せない。

## 呼び名と役割

方式は「拍・小節解析によるカウント同期」。Beat This!は制作時の拍・小節頭の推定器。完成した同期データを既存の960tickコンパイラとtempo-mapで再生する。利用時に推定器を動かさない。

制作側: 原本を保全 → 波形から解析 → 拍・小節の候補を試聴 → 必要な修正 → 基本カウント／ルーティン・開始順・速度・区間端を確認 → 完成音源と同期データを登録する。

利用者側: 「使う」→ 曲を選ぶ → 必要なら保存したルーティンと速さを選ぶ → 再生。波形・BPM推定値・confidence・拍の修正・楽曲アップロードは出さない。

## 今回の接続

- `MusicScreen`の「練習の設定」内に「どのカウントで練習しますか？」を追加。同じ種目の、既存compilerが再生できる保存済みルーティンだけを選べる。保存したものがない場合は項目を増やさず、基本カウントで使える。
- ルーティン選択時は名前を表示し、最初／最後のフィガーを指定できる。選択と範囲はこの訪問の間だけ。保存したルーティン本体は一切変更しない。制作用の実験例は利用者の一覧へ追加しない。
- 再生中は現在のフィガー名と、そのフィガーのカウント帯。帯・声・切替はセッションが渡した同じtickから表示する。曲先の準備で先頭フィガーを消費しない。同じ区間をくり返すときは曲先の準備も各回に含め、その順番を設定内で案内する。声先の曲前合図は最初のみ。
- 区間より長いルーティンは再生と書出しを止め、設定を閉じても理由を表示。指定範囲を勝手に切り詰めない。音楽だけを聞くときにはルーティンの長さで再生を妨げない。
- 音声作成は同じ`compileMusicProgram`とschedulerを使用。ルーティン・範囲・声・曲の設定を変えたら、古い書出しを破棄する。
- 初期4操作群／設定を開いたとき最大9操作群。短い画面では余白だけを調整し、カウントと48px以上の操作を保つ。ルーティンがない時の従来の画面は維持。

## 制作物の受入と、残すもの

完成曲を登録するときは原本hash、同期データrevision、種目と拍子、確認した区間と先頭拍、3速度の素材、音量、試聴確認の担当・日付を一緒に保管する。元の解析結果と完成データは別に残し、未確認の自動推定を完成扱いにしない。音楽を伸ばしたり未解析部分へ一定BPMを外挿して埋めない。

原本・解析結果・モデル・波形確認画面は制作環境に置く。公開buildには制作画面や試聴原本を含めない。完成曲を配信する段階では、完成した音声素材と必要な拍時刻／区間のデータだけを渡す。制作環境のAPIやファイルパスを配信元として使わない。

現在は開発用の試聴曲・6小節区間で確認中。長いルーティン用には、こちらでより長い連続区間を確認して登録する必要がある。本番向けカタログ・配信元・有料機能の解放・公開は今後の作業で、今回の接続では有効化しない。既存の試聴中表示も残す。

## 再開と検証

`http://127.0.0.1:5195/#/use/music/waltz-33445d26a14c`。「練習の設定」で保存済みルーティンを選ぶ。持っていない場合は先に「作る」で作成・保存する。確認画面にある実験例は端末の保存領域へ挿入していない。

- `npm test`, `npm run typecheck`, `npm run timing:compare`, `npm run build`
- `npm run ui:check:music`（従来の基本カウント）
- `npm run smoke:music:use-routines`（隔離profileの保存ルーティン、実再生・WAV・波形非表示・解析API不使用・範囲・保存内容不変・日英・4画面サイズ・WCAG）
- `/tmp/dc-music-analysis-venv/bin/python tools/music-probe/verify-exports.py output/music-probe/use-routine-browser-evidence.json`

証拠は`output/music-probe/use-routine-browser-evidence.json`と`use-routine-export-verification.json`。自動テストの波形照合は完成した拍データへの声の配置検査で、音楽の拍自体の人の確認を代替しない。
