## 4. 直した物

1. **段5の文を句の切れ目で折る（Chrome・Android）**: `base.css` に `.dc-dock-note, .dc-backup-tip, .dc-result, .dc-receive .dc-alert-text, .dc-receive-item, .dc-receive-note, .dc-receive .dc-body { word-break: auto-phrase; }`（既にある `.dc-receive-help`・`.dc-record .dc-alert-text` と同じ型）。「作れま／す。」「送／ってください」「ルーティ／ン」「ず／っと」「受け取れませ／ん。」「ア／プリ」が Chrome で句の切れ目に。iOS Safari は変わらない（Open question 3）。
2. **M2・M3（受け取りの保存の途中の失敗）**: `ImportWriter.voiceSaved?(pack)` を足し、`commitImport` は声を書けたら**すぐ**呼ぶ（古い声を消す前）。S10 はそこで声を選ぶ（`update(chooseVoice(packSelection(pack)))`）ので、その後でルーティンが書けなくても選択が消えた声を指さない。`commitImport(...).catch(() => false)` で投げた時も「保存できませんでした」に。単体テスト 1 件（`plan-import.test.ts`「the new voice is chosen as soon as it is saved…」）。シミュレーターの c で、受け取った声が S2 のチップに出ることを実経路で確かめた。

## 5. Open question（Fable へ。推奨の既定つき）

1. **S7 で声が 2 本以上の時、548 で「自分の声を録音する」がタブの下に半分隠れる**。— 既定: 600px 未満の高さでは「ファイルから受け取る」と「自分の声を録音する」を**横 1 行に並べる**（白・紺の 2 つ・各 `flex:1`・2 行まで）。行の高さ 56＋余白で、2 本の時に両方が初期表示に入る。3 本以上は一覧をスクロールする（主ボタンを下の帯に固定する案はタブと二重の帯になり S7 の型を変えるので採らない）。直す時に ui:check の「S7 3 本」に 548 の firstView を足す。
2. **S6「ルーティンを配る」から来た時、ルーティンの一覧が 548 の下**。— 既定: 共有の意図（`takeShareIntent`）が「S6 から・声の指定なし」の時は、**ルーティンの見出しまで初期スクロールする**のでなく、**並びを 名前 → ルーティン → 声 にする**（S6 の入口は「ルーティンを配る」と言っているので）。S7・S8 から（声の指定あり）は今の並びのまま。
3. **iOS Safari の「す。」だけの行・句の中の改行**（「ここで選べま／す。」「"ファイ／ル"」）。CSS では直せない（`auto-phrase` は Chrome だけ、`pretty`・`balance` は句の中で折る）。— 既定: **段5では据え置き**（HANDOVER §9 の「好み」の扱い・手動の改行は入れない）。実機の SE で気になったら、文言を短くする（例「LINE で届いたファイルは、先に「"ファイル"に保存」します。」）のは PO の文言の判断。
4. **S9 で録音もルーティンも無い時、帯が「声かルーティンを選ぶと、ファイルを作れます。」**（選べる物が無い）。— 既定: 両方無い時は帯の 1 行を出さない（上の 2 行「…まだありません。」で足りる）。録音・ルーティン作りへの道は足さない（S9 の操作数を増やさない・戻るで S6 に戻れる）。
5. **S10「受け取りました」の出口が 2 つ（上の「戻る」と下の「ホームへ」）**。— 既定: **このまま**。集中画面は全部「戻る」を持つ型（Ruling の S8 完成も同じ）で、「戻る」も受け取った物を消さない。主は紺の 1 つで迷わない。
6. **S9 で声をファイルの形にできなかった時、黙って「入れない」に戻る**（`exportVoiceForBundle` の失敗。録音のデータが壊れた時くらいで、まず起きない）。— 既定: 声の 2 択の下に 1 行「この声はファイルにできませんでした。」（依頼形にしない・`.dc-hint`）。文言の追加なので段6以降でも可。
