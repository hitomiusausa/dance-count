# 波形から拍・小節頭を推定してカウントへ接続する

2026-10-23 / うさこ。ひちゃんの依頼: 曲の波形を見て、小節を把握しカウントを合わせるプログラムを実装する。

## 根本の不足

従来のlibrosa候補の偶数点だけを1拍にする方式は、拍の密度を変えても音楽の拍・小節頭を推定していなかった。波形の最大音量だけを小節頭にすることも、弱起やシンコペーションには対応しない。

## 実装する流れ

1. 元WAVのSHA256を記録し、Mac内で解析。波形からlog-melスペクトログラムを計算し、[Beat This!の公式実装](https://github.com/CPJKU/beat_this)で拍と小節頭のフレームごとの活性を同時推定する。コード・モデルの一次ライセンスはMIT。学習データや元曲の権利を自動承認する意味にはしない。
2. 小節頭の間に4拍あるか、拍間隔・活性の弱さ・coverageを検査。間違った拍子や拍抜けを強制補間して4拍にせず、要確認として記録する。
3. 6小節連続した候補だけを元曲の前／中／後から選ぶ。不安定な末尾から離れる必要があれば45秒以内で移動し、使える区間がなければ止める。
4. 制作側の波形確認画面で、全曲の音量波形、要確認部分、2小節ずつの拍・数字・小節頭・再生位置を表示。既存エンジンと同じ時間写像で音楽・声・表示を動かす。
5. 練習アプリとWAV出力は同じ新しい拍地図を読む。区間ごとに小節頭のanchorを持つ。前の区間での誤検出が次の区間の数字を回転させない。

## 境界

- 音楽のアップロード、外部推論API、課金APIは追加しない。モデルの初回download以外はローカル処理。
- 原本・従来解析を保持。重いモデルと生成JSONはGit対象外。プロダクションbundleとprecacheへモデル・曲・解析を含めない。
- モデルの活性値は正解確率ではない。出力はmachine-candidate。人の音楽審査なしで販売審査済みにしない。
- クライアントに解析モデルを載せない。各種目3曲を用意する制作工程の道具とし、普段の練習画面の設定は増やさない。
- checkpointはSHA256 `8c328b45f59d8dd3dff219253ff6a8d6482be57d0133a29140e2febbf8eb8331`固定。公式配布元の503時は同一hashの再配布を使い、weight-only読込する。出典・versionを記録する。

## 受入

- 可変テンポ・小節頭が全体index%4と異なる例・誤拍子・短すぎる偽拍・弱い活性・原本hash違いを検査する。
- 実曲の3区間で、波形／小節頭／実音再生／開始順／速度／保存したWAVを確認。機械時刻への配置精度と音楽的な正解を区別する。
- 既存テスト・型・timing golden・build除外、日英の音楽UIも実行する。
- 原本と関係ないユーザーのフィガー／xlsxを保護し、ローカルとGitHub作業枝へバックアップする。公開deployは行わない。
