# 練習系2画面 UI刷新 設計書

日付: 2026-07-15
対象: `public/practice.html`（シンプル再生）・`public/routine-editor.html`（ルーティン練習・編集）
決定者: ひとみうさ（ブラウザモックによる選択: 見た目=B「清潔感を進化」、編集導線=B「下固定バー＋タップ展開」）

## 1. 目的とユーザー

- 主ユーザーは**年配の方を含む一般の練習者**と**外国人**（日本語が読めない）。
- 端末は**スマホ最優先**（練習場で使う）、**PC**も対応。タブレットはその中間として自然に吸収する。
- 編集画面は「練習する人」と「ルーティンを組む人」が**同じくらい**使う。編集操作を隠しすぎない。

## 2. 決定事項（モック選択の記録）

| 論点 | 決定 | 却下案 |
|---|---|---|
| 見た目 | 現行の青×白を継承しつつ大型化・アイコン化（B） | クリーム地の温かい系(A)、黒×金のダーク(C) |
| 編集画面の導線 | 再生バーを下に固定＋タップしたカードだけ編集ボタンが開く（B） | 編集ボタン常時表示(A)※一度Aを選択後Bへ変更確定、上固定＋⋮メニュー(C) |
| アイコン | **SVG線画（Lucide系）のみ。絵文字は使わない** | 絵文字 |
| ラベル | 主要操作は必ず「アイコン＋短いラベル」併記。ラベルは既存の日英UI切替に連動 | アイコン単独、文字単独 |
| フィガー追加 | ヘッダーの「＋追加」は廃止。**カード一覧末尾に横幅いっぱいの「＋ フィガーを追加」**（追加される場所にボタンを置く）。一覧が空でも同じ位置に表示 | ヘッダー右上の小さな追加ボタン（何を追加するか不明瞭とPO指摘） |

## 3. 共通デザイン基盤

新規ファイル:

- `public/assets/ui.css` — 共通トークンと部品。2ページのインラインstyleから共通部分を移す。
- `public/assets/icons.svg` — SVGスプライト（`<symbol>`集）。各ページは `<use href="assets/icons.svg#i-play">` で参照。

### トークン（ui.css の CSS変数）

- 配色: 背景 淡青グレー系 / カード 白 / 主要アクション 青 / 文字 濃紺。**全ての文字・地の組で コントラスト比 ≥ 4.5:1**（機械チェック対象）。
- 文字: 基本 18px。カウント表示・フィガー名はそれ以上。行間ゆったり。
- タッチ目標: 最小 **44px**、主要ボタン（再生・追加・削除確認）は **48px**（機械チェック対象）。
- 角丸・影・余白は単一トークンで統一（radius, shadow, spacing の場当たり値を作らない）。

### アイコン語彙（初期セット）

play / stop / repeat / metronome（メトロノーム型。音声=スピーカー型と必ず描き分ける） / gauge(速度) / voice(スピーカー) / plus / copy / trash / pencil(変更) / grip(⠿) / globe(言語) / chevron(開閉) / undo / redo / check / arrow-up / arrow-down

- すべて stroke ベース・currentColor。意味が伝わる最小限の線画。
- ラベル文言は `src/v2/ui-messages.js` の既存日英辞書に追加して連動させる。

## 4. シンプル再生画面

- 1画面構成は維持。部品を大型化:
  - 「練習内容・種目・カウント」のセレクトは大きく（高さ48px・文字18px以上）。
  - 「繰り返す・メトロノーム」のチェックボックス → **アイコン＋ラベルの大型トグルボタン**（押すと塗りが変わる）。カウントインも同列の大型コントロールに。
  - 再生ボタンは**画面下部固定**の大型ボタン（編集画面の下バーと同じ操作感・スクロールしても常に押せる）。
  - 言語切替は右上に **globeアイコン＋「日本語/English」** の見えるボタン（現行の「画面表示」selectを置換。内部の言語設定キーは不変）。
- BPMスライダーは現状維持しつつ、つまみを44px級に拡大。数値表示は大きく。

## 5. 編集画面（導線B）

### 上部（ヘッダー）

- ルーティン選択・下書き名。**「＋追加」ボタンは置かない**。
- 「シンプル再生へ」の切替リンクはアイコン＋ラベルのボタンに。

### カード一覧

- 通常カード: `⠿ハンドル｜番号｜フィガー名｜カウント` のみのすっきり表示。
- **タップで選択したカードだけ展開**: 拍ブロック（小節内ハイライト）＋「試聴・変更・複製・削除」（アイコン＋ラベル、各44px以上）。
- **再生中の表示**: 全体試聴・範囲再生中は、いま鳴っているフィガーのカードが自動で展開状態になり拍ハイライトが見える（再生位置の移動に追従。手動選択とは区別し、停止で元に戻る）。
- 「変更」= 現行のフィガー名候補ドロップダウン＋カウント自動入力（既存挙動そのまま、展開内に表示）。
- 並べ替え: 大きくなった⠿ハンドルのドラッグ＋既存のキーボード上下矢印を維持。ドラッグ中の挿入位置表示も維持。
- 削除: 既存の確認ダイアログ＋Undo を維持。
- 一覧末尾: 横幅いっぱいの **「＋ フィガーを追加」**。

### 下部固定の再生バー

- 大型の再生/停止（丸・48px以上）を中央に、左右に「繰り返し・速度(BPM)・音声・カウントイン」をアイコン＋ラベルで配置。
- 現行の「浮いてカードを隠すバー」は廃止。バーの高さぶん一覧下部に余白を確保し、最後のカードが隠れないようにする。
- 速度・音声・カウントインはタップでバー上部にパネルが開く（バー自体は常に同じ位置）。

### 段階表示（progressive disclosure）

- 「音声タイミング微調整」「元データに戻す」「録音・音声パック管理へのリンク」は**「詳細設定」折りたたみ**へ移動（AGENTS.md の方針）。
- Undo/Redo はヘッダー近くに残す（編集の基本操作のため隠さない）。

## 6. 実装方式

- **ロジック不変**: `src/v2/` モジュール、localStorage/IndexedDBの保存形式、イベント処理、下書き互換はそのまま。**DOM構造とCSSのみ再構成**。
- 2ページのインラインstyleのうち共通部分を `ui.css` へ、ページ固有部分は各ページに残す。
- アイコンは `icons.svg` スプライトを `<use>` 参照（http配信前提。file://直開きは対象外＝現行どおり `npm start` で使う）。
- 機械可読部の不変: フィガーカウントの表記・パーサ・保存キーには一切触れない。

## 7. 受け入れ条件（検証ゲート）

### 機械ゲート

1. `npm test` 全緑（既存88件）。
2. 新規チェックスクリプト `tools/check-ui-accessibility.js`（Playwright使用）:
   - 両画面・スマホ幅(390px)/PC幅(1280px)で、可視の操作要素すべてが **44×44px以上**（主要ボタン48px）。
   - 文字と背景の実測コントラスト比 **≥ 4.5:1**（computed styleから算出）。
   - コンソールエラー 0件。

### 目視（指名ケース）

スマホ幅とPC幅の両方で:

1. シンプル再生: 種目選択→再生→カウント表示が光る→停止。トグルの状態が見た目で分かる。
2. 編集: ルーティン選択→カードをタップ→展開→試聴→複製→削除→Undo。
3. 並べ替え: ドラッグとキーボードの両方。
4. 「＋ フィガーを追加」が一覧末尾に出て、追加後にその位置へカードが現れる。
5. 言語切替: English にして全ラベルが英語になる（アイコンは共通）。
6. 下バーが最後のカードを隠さない。

## 8. 二次リスク・注意

- DOM再構成により既存のID/クラスを参照するページ内JSが壊れやすい。**移行はページ内JSの参照箇所を洗い出してから**行い、1画面ずつ完結させる。
- 拍ブロックのハイライトは `timeline-view-model.js` 由来のクラス付与に依存。クラス名は変えない。
- 下書きデータ（localStorage）を持つ既存ユーザーがそのまま開けること（保存形式不変で担保、目視でも確認）。
- 録音・レビュー系画面は対象外（今回は触らない）。ui.css は将来それらにも使える形にするが、適用は別作業。
